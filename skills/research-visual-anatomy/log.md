# Цвет и типографика (В5)

> v0 (2026-09-30). Записан по обсуждению с Владом (В5 ✓ 30.09). Скрипт `palette.py` лежит рядом с этим файлом (Python + Pillow, numpy не нужен); проверен на PNG RGB / RGBA / палитровом / сером / 16-битном, JPG, WebP, от 1×1 до 1206×2622. v0.1 (30.09, уроки запуска В Mayors): `--mobbin`, фото — прямоугольником, `--pick` / `--scan-*` с `--crop`, `--text`, `--font`; рядом `rtl.py`.

## 1. Зачем
Прошлые версии брали цвета, радиусы и отступы из дефолтов фреймворков (Tailwind, Material) — «без усилий». Здесь цвет и шрифт **снимаются с рефов выбранного стиля числами**, чтобы Дизайн строил свою палитру и шкалу из измеренного, а критик мог спросить «откуда этот токен».

**Граница:** Ресерч **измеряет и описывает**. Палитру (OKLCH-шкалы, свои hex), шкалу шрифта и токены **строит Дизайн**. AA (текст 4.5, крупный 3, нетекстовое 3) — пол, AAA не требуем. Цвет — не единственный носитель смысла.

## 2. Вход
- `02-research/visual/style.md` → «Базовый стиль ✓» и экраны выбранного кандидата.
- `02-research/visual/refs.md` — экраны уровня «страница» и «детали» (их же и мерить).
- Полные картинки: `crops/src/*` (Mobbin `image_url`, @3x) — **не превью**.
- `STATE.md` — шрифт проекта (Mayors: **Julius** Влада — Light 300 / Medium 500 / Bold 700, иврит + цифры; нет латиницы, ₪, `/ · – … ×`, кернинга и Regular 400; цифры равной ширины — замер `--font`, `color-type.md`), решения по статусам.
- Бриф — 50+ (основной ≥ 17, вторичный ≥ 15), RTL, бренд заказчика (если есть — его цвета и шрифты приоритетнее).
- `model.md` — реальный контент: максимальные суммы, длинные названия, смешанные строки иврит + латиница + цифры.

## 3. Что искать (чек-лист)

**Цвет** — на 4–6 экранах выбранного стиля (+ детали):
- [ ] Поверхности: фон, карточки, панели — hex, OKLCH, доля, где.
- [ ] Нейтрали: сколько ступеней, тёплые / холодные; **контраст каждого текста к его фону** (WCAG).
- [ ] Акцент: какой, **список мест** (кнопка, ссылка, активная вкладка, статус), число акцентов.
- [ ] Статусы: цвета успех / ожидание / ошибка / нужно действие — как устроены (тон текста, подложка), контраст.
- [ ] Доли по площади **без фото**: светлые нейтрали / тёмные / хроматика.
- [ ] Тёмные зоны: таббар, плашки, тёмные карточки.
- [ ] Цвет не единственный носитель (слово / значок рядом).

**Типографика:**
- [ ] Класс гарнитуры рефа (геометрический / гуманистический / нео-гротеск; антиква → в иврите заменить).
- [ ] 2–3 ивритских аналога **без засечек** (шрифт проекта — кандидат №1, где уместен) с проверкой: цифры, латиница для смешанных строк, ₪, веса, есть ли в Figma.
- [ ] Шкала уровней: крупное число · заголовок экрана · секции · карточки · основной · вторичный · подпись — размер, высота строки, вес, трекинг; соотношения; число весов.
- [ ] **Заголовки** (просьба Влада): где стоят, отступы, прокрутка, макс. строк, замена КАПС-меток.
- [ ] Суммы и ₪: кегль знака, отступ, позиция, моноширинные (табличные) цифры.
- [ ] Визуальная высота иврита против латиницы и цифр в одной строке.

## 4. Как решать

### 4.1 Цветовая анатомия — скриптом
Hex «на глаз» не пишется. Скрипт: `plugin/skills/research-visual-anatomy/palette.py` (запуск: `python palette.py …`; при кракозябрах в консоли Windows — `set PYTHONIOENCODING=utf-8`).

```bash
# полный анализ экрана (scale определяется по ширине: 1170/1179/1206/1290… → @3x)
python palette.py crops/src/S1-3.png --json anatomy/S1-3.json
# исходник Mobbin (image_url): снизу полоса «curated by Mobbin» 40 pt — отрезать, иначе она «тёмная поверхность»
python palette.py crops/src/S1-3.webp --mobbin
# фото определяются автоматически; если ошибся — исключить вручную (pt)
python palette.py shot.png --exclude 0,96,393,210 --no-auto-photo
# только блок
python palette.py shot.png --crop 16,420,361,180
# точечно: цвет в точке, отрезки вдоль строки/столбца (поля, ширины, зазоры в pt)
python palette.py shot.png --pick 40,212 --scan-row 212 --scan-col 20
# текст: фон, «ядро» чернил (без сглаживания), контраст WCAG, высота над базовой (≈ кегль), шаг базовых
python palette.py shot.png --text 16,120,300,60
# шрифт: глифы из списка --need (иврит, цифры, ₪, / · – … ×), табличные цифры, кернинг, штрих по весам
python palette.py --font fonts/Julius/Julius-v1-equal-Medium.ttf --font "gf/Inter[opsz,wght].ttf"
# контраст пары (для проверки наших будущих токенов тоже)
python palette.py --pair "#6B6B6B" "#F4F1EC"
```

Все координаты (`--crop`, `--exclude`, `--pick`, `--scan-*`, `--text`, места в выводе) — **в pt исходной картинки**, и с `--crop` тоже.

Что выдаёт: поверхности (≥ 3%) · прочие цвета (текст, линии, значки, мелкие плашки) с поверхностью под ними и контрастом WCAG · хроматику по семьям тона с местами (рамки в pt) · доли без фото · тёмные зоны · OKLCH для каждого цвета. Формулы: относительная яркость и контраст WCAG 2.x, OKLab / OKLCH (Оттосон).

**Как читать честно:**
- Кластеры — эвристика. Строка «возможно сглаживание» = серый между текстом и фоном; проверить `--pick` на толстом штрихе.
- WebP / JPG сжаты: hex плавает на 1–3 единицы, у мелкого цветного текста больше; вокруг цветных кнопок бывают «ореолы» (бледные цвета с долей < 0.1%) — не считать их цветом системы. Ключевые цвета перепроверить `--pick` на большой плоской области.
- «Акцент-кандидат» — просто самый частый хроматический цвет; **что это** (кнопка, статус, ссылка) — определить глазами по местам.
- Автопоиск фото ловит пёстрые плитки и **достраивает фото до прямоугольника** (плоское небо / вода внутри и у края фото иначе уходят в «акцент»: на Mayors «синие ссылки» С3-2 и «акцент» С3-1 оказались небом). Хроматика у края фото помечается «небо / вода?» — проверить глазами; при сомнении — `--exclude` прямоугольник фото целиком. Иллюстрации из плоских цветов фото не считаются — если искажают доли, `--exclude`. Тёмные края фото тоже не интерфейс.
- Контраст текста — `--text` по блоку, а не строка «прочие цвета» (там сглаживание и соседние цвета).

**Статусы:** скрипт не знает смысла — по местам и глазами назвать, какой цвет какой статус, и записать тон текста, подложку, контраст к подложке.

**Сводка по стилю:** по 4–6 экранам — повторяющееся (фон всегда тёплый ≈ OKLCH L 96%, C 0.007; один акцент в 5 из 6; статусы только тоном текста). Это вход для палитры Дизайна.

### 4.2 Типографика: класс и ивритские аналоги
1. Класс гарнитуры рефа — по форме (a, g, R, цифры 1 / 4 / 7), по названию, если известно (SF Pro, Inter, GT America…).
2. **2–3 ивритских аналога без засечек** (Влад не использует антикву в иврите). Кандидат №1 — **шрифт проекта**, если он есть (Mayors — Julius) и подходит по классу / весам. Кандидаты из свободных (проверить на дату): Heebo, Assistant, Rubik (округлый), Noto Sans Hebrew, IBM Plex Sans Hebrew, Open Sans (иврит), Varela Round, Secular One (только заголовки); платные — с пометкой «нужна лицензия».
3. Для каждого аналога — таблица проверки:

| Шрифт | Класс | Веса | Цифры (табличные?) | Латиница для смешанных строк | ₪ | Есть в Figma | Замечание |
|---|---|---|---|---|---|---|---|

Колонки «Веса · цифры · латиница · ₪» — **по файлу, не по описанию:** `palette.py --font <ttf>` (глифы, ширины цифр, кернинг — нужен `fontTools`: `python -m pip install fonttools`; без него скрипт скажет и посчитает только штрих). Штрих — по TTF (рендер глифа 1000 px), не по скриншоту: у вариативного партнёра скрипт выдаёт штрих по весам 100–900 → **вес партнёра подбирается по штриху** к весам шрифта проекта (Mayors: Inter 350 / 650 / 900 ↔ Julius 300 / 500 / 700). Этот же штрих — вход для иконок (`research-assets` §4.1).

Если у шрифта нет латиницы или ₪ (Julius) — назвать **пару**: какой шрифт даёт латиницу, цифры и ₪ и как их подогнать по высоте (§4.5).

**Образцы на иврите** (лестница шкалы, пары, суммы) рисовать Pillow через `rtl.py` (рядом с этим файлом): прогоны в логическом порядке, иврит разворачивается, суммы и латиница — LTR-группой `{'ltr': [...]}`, недостающие знаки — шрифтом-партнёром. Шрифты — через `rtl.font()` (базовая раскладка): если в Pillow есть raqm, он развернёт иврит второй раз. Проверить картинку глазами.

### 4.3 Шкала уровней
Замер: высота цифр / заглавных латиницы ≈ 0.7 кегля у большинства гротесков → кегль ≈ высота цифры / 0.7 (в pt, после деления на 3). Высота строки — расстояние между базовыми линиями двух строк (`palette.py --text` даёт высоту над базовой и шаг базовых в pt). Если реф на системном шрифте iOS — сверить с системной шкалой (Large Title 34, Title 1 28, Title 2 22, Title 3 20, Headline 17 semibold, Body 17, Callout 16, Subheadline 15, Footnote 13, Caption 12 / 11) и писать точное значение.

| Уровень | Кегль | Строка | Вес | Трекинг | Где у рефа |
|---|---|---|---|---|---|
| Крупное число | | | | | |
| Заголовок экрана | | | | | |
| Заголовок секции | | | | | |
| Заголовок карточки | | | | | |
| Основной | | | | | |
| Вторичный | | | | | |
| Подпись | | | | | |

Плюс: **соотношения** (крупное / основной, заголовок / основной), **число весов** на экране, чем создаётся иерархия (размер / вес / цвет). Для 50+: наша шкала будет +1–2 px к измеренной (основной ≥ 17) — это решает Дизайн, здесь только пометка.

### 4.4 Заголовки (просьба Влада)
Отдельной таблицей по рефам:
- **Где стоят:** в шапке (навбар) или в контенте; край начала строки или центр.
- **Отступы:** сверху и снизу (обычно сверху > снизу — заголовок «принадлежит» следующему блоку, P4), от края экрана.
- **Прокрутка:** крупный заголовок сворачивается в шапку (конвенция iOS), остаётся, уезжает; появляется ли разделитель шапки.
- **Макс. строк** и что с длинным: перенос, «…», уменьшение.
- **КАПС-метки** (надзаголовки «UPCOMING», «STATUS»): в иврите прописных нет → чем заменить: вес + меньший кегль + цвет, осторожная разрядка (проверить на шрифте проекта, не выглядит ли ошибкой вёрстки).
- Соседство заголовка и крупного числа (на Mayors №8 заголовок и сумма оба 32 Bold — фокус должен остаться на сумме).

### 4.5 Суммы и ₪
- Кегль знака валюты относительно числа (равный / 60–75%), вес, отступ до числа, позиция знака (до / после) — **снять у израильских продуктов** (банки, Bit), не придумывать.
- Табличные (моноширинные) цифры в колонках и списках сумм — есть ли у рефа, есть ли у кандидатов-шрифтов.
- Суммы и даты в RTL-строке — в LTR-изоляции.
- **Визуальная высота:** в смешанной строке иврит + цифры + латиница ивритские буквы обычно ниже цифр и заглавных латиницы → измерить отношение высоты букв иврита к высоте цифр у шрифта-кандидата и пары; если пара шрифтов — на сколько % подогнать кегль латиницы / цифр.

## 6. Типичные провалы
- Hex «на глаз» или с превью, а не скриптом по полной картинке.
- Цвет снят с фото и засчитан в палитру UI (фото не исключено; небо / вода у края фото приняты за акцент).
- Исходник Mobbin без `--mobbin` — полоса «curated by Mobbin» посчитана тёмной зоной.
- Контраст текста взят из «прочих цветов» вместо `--text`; веса и глифы шрифта — по описанию, а не по файлу.
- Сглаживание или «ореол» сжатия записаны как цвет системы.
- Ресерч построил палитру (OKLCH-шкалы, свои hex) — это работа Дизайна.
- Бледный текст рефа — повод выкинуть реф (для 50+ стиль берём, контраст чиним).
- Аналог шрифта с засечками для иврита; капитель перенесена как есть.
- Шрифт проекта предложен без проверки латиницы, ₪ и цифр.
- Кегли по превью без деления на 3; нет высоты строки.
- Заголовки описаны только размером — без места, отступов, прокрутки, длины.
- Позиция ₪ придумана, а не снята у израильских продуктов.
