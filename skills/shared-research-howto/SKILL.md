# Как ищут ресерчеры (общее)

Загрузка инструментов Figma / Mobbin, зоны, окружение сессии, отчёт — `shared-runtime` §3–4, §6. Здесь — только то, чего там нет.

## 1. Что считается рефом
- **Реф = рабочий экран внутри продукта** после входа (главная, список, детали, форма, sheet, пустое состояние). Не реф: hero / промо / лендинг, скрин магазина с подписью или рамкой телефона, мокап «телефон в руке», коллаж экранов под углом, онбординг-маркетинг. Скрин из магазина — только чистый снимок экрана целиком.
- **Платформа совпадает** с нашей. Веб-реф для мобайла — только за стиль, с пометкой «веб».
- **Лестница доверия** (выше — надёжнее): 1 Mobbin · 2 скрины самих продуктов (веб-версия, чистые снимки магазинов, кадры видеообзоров с экраном целиком) · 3 Behance-кейс про запущенный продукт · 4 Pinterest / Dribbble / Behance-концепты — всегда с пометкой **«концепт»**; годятся донором **стиля и приёма**, а донором раскладки — после проверки «наш состав и иврит ложатся, нормы платформы и AA держатся» (✓ Влад 22.11: «не только с Mobbin, а и с Пинтереста — там много крутых и концептуальных интерфейсов»).
- У каждого рефа — метка **«живой» / «концепт»**. Норма «≥ 2 живых» концептами не закрывается (проверка: в счёте живых нет ни одного с пометкой «концепт»).
- Названный заказчиком продукт («как X») — сначала его живые экраны; сайт-витрина не реф. Нет в Mobbin → в первый день лиду: «нужны скрины от Влада».
- Решённое Владом (STATE ✓) заново не ищется — только недостающее.

## 2. Запросы в Mobbin
- `search_screens` (`deep`) — экраны; блок ищется как экран, где он есть, и вырезается кропом. `search_flows` — блок живёт в потоке (шаги сделки, оплата). `search_sections` — только секции веб-сайтов; для мобильных блоков не применять.
- Запрос на английском описывает **видимые признаки и функцию** («upcoming installment card with due date and pay button», «home screen with large thin headline and hairline dividers»). Без слов стиля («modern», «clean», «editorial») и без ниши («real estate app»); бренд — только как фильтр конкретного продукта («Airbnb trips screen»). Проверка: в запросе нет слова-оценки и названия ниши.
- Mobbin почти весь LTR, израильских продуктов нет → RTL-источники вписывать в план заранее (продукт · где смотреть · время). Не успели — в выходе строка «RTL не смотрели», не тишина.

## 3. Другие источники
- **Dribbble**: к запросу добавлять «app screen UI», «mobile app interface», «dashboard»; брать только плоские шоты (мокап в руках, презентация — мимо). Всё — концепты.
- **Pinterest — обязательный источник для стиля и приёмов** (✓ Влад 22.11). Вход требуется со второго запроса → **Chrome Влада** (Claude in Chrome, его сессия; аккаунтом — только поиск и просмотр, ничего не сохранять и не подписываться). Запросы на английском: функция + «mobile app ui» / «app interface concept» / «dashboard ui» («home screen ui big number tiles», «apartment building app ui»); с хорошего пина — «Ещё похожие» на 1–2 шага. Брать только плоский экран целиком (без рук, мокапов под углом, коллажей), крупнейший `src` пина; в карточке — URL пина и, если виден, автор / исходный Dribbble / Behance. Доски Влада на Pinterest (если даст ссылку) — источник №0, выше Mobbin по вкусу.
- **Behance**: может не открыться → Chrome Влада или в выходе «не смотрели». Время на Pinterest / Dribbble / Behance — из плана, не «если останется».
- Региональные продукты: веб-версии браузером, картинки магазинов — «≈» и только за конвенции, видеообзоры. Unsplash — только браузером, своя вкладка; `premium / plus` проверять на странице.

## 4. Картинки: скачать, подготовить, назвать
- Исходники — `02-research/visual/crops/src/`, кропы — `crops/<ID>.png`. Имена файлов и слоёв — **латиницей** (Б4-2 → `B4-2.png`; таблица ID — `research-visual-board` §1).
- Mobbin: `curl -sL -o crops/src/B4-2.webp "<image_url>"` сразу при находке.
- Сайты / Dribbble / Behance / Pinterest: оригинал — самый крупный `src` / `srcset` у `img` или `og:image` (`read_page` / `javascript_tool`), скачать `curl`. Dribbble — `cdn.dribbble.com/userupload/…`; Behance — `mir-s3-cdn-cf.behance.net/project_modules/…` (`max_1200` / `fs`); Pinterest — `i.pinimg.com/…`, размер в пути → `originals`. Оригинал не достать → снимок экрана Pillow `ImageGrab.grab(bbox=…)` при масштабе 100 %, замеры — «≈».
- Mobbin `image_url` снизу содержит полосу «curated by Mobbin» 40 pt → отрезать (120 px при @3x) до доски и замеров; в `palette.py` — `--mobbin`.
- **Масштаб**: iOS @3x → делить на 3, писать pt. Число по превью — только с «≈» и пометкой «оценка»; замер — по оригиналу (`research-visual-anatomy`).
- Кроп блока — блок + контекст 8–16 pt (Pillow, координаты pt × scale). Целый экран — без кропа. Файл ≤ 10 МБ; для доски хватает ширины 600 px, полное разрешение остаётся в `crops/src/`.

## 5. Figma: `upload_assets` по шагам
1. `use_figma`: прямоугольники-места нужного размера, имена `Crop/<ID>`; вернуть id.
2. `upload_assets({ fileKey, currentPageId, count, nodeIds, scaleMode: "FILL" })` → одноразовые `submitUrl`: живут 10 минут, ≤ 60 за вызов — вызывать, когда кропы уже готовы; `currentPageId` обязателен (иначе картинка уедет на первую страницу).
3. `curl -s -X POST -H "Content-Type: image/png" --data-binary "@crops/B4-2.png" "<submitUrl>"` → `{"success":true,"imageHash":…}`.
4. Проверка: `fills[0].type === "IMAGE"` у каждого узла и `node.screenshot()` внутри `use_figma` (серверный `get_screenshot` переворачивает иврит).
5. Повтор кропа — копировать `imageHash` в `fills`, не грузить заново. SVG — `figma.createNodeFromSvg(svg)` или `upload_assets` с `image/svg+xml`.
- Сторона > 4096 px — резать Pillow на куски ≤ 4096 (каждый — свой прямоугольник, встык) или уменьшить до ширины доски.
- Не сработало → картинки ссылками не подменять: кропы в `crops/`, на доске пустые места с ID, первой строкой отчёта лиду.

## 6. Постоянные правила
- Позиции — **«начало / конец строки»**, не «слева / справа» (проверка: в выходе нет «слева / справа» про элементы интерфейса).
- У каждого LTR-рефа строка **«что ломается при зеркале»**: оси и прогресс, шевроны, асимметрия (вырез в углу, полоса на краю), числа и даты (LTR внутри RTL), длина иврита на контенте из `model.md`.
- **50+ = понятность** (`shared-ux-principles` P15), не режим для слабовидящих и не крупный шрифт: реф с бледным текстом не выкидывается — контраст чиним до AA, размеры по нормам платформы. В разборе в рисках — понятность: действие без слова, иконка без подписи, жест без кнопки.
- **Иврит — без засечек**; антиква и капитель переводятся в гротеск (контраст размера и веса). Прописных нет — КАПС-метки заменяются весом / кеглем / цветом.
- STATE читается первым; решение Влада главнее брифа (расхождение → лиду).
- «Чисто», «воздушно», «современно» без числа не принимаются: размеры, отступы, радиусы, кегли, веса, hex, пропорции.
