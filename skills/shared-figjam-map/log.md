# Карта проекта в FigJam

> v0 (2026-09-29). Формат утверждён Владом. Карта нужна Владу, чтобы «углубиться в проект».

## 1. Перед началом

- Загрузить скиллы `figma:figma-use` и `figma:figma-use-figjam` (обязательно перед `use_figma`).
- Доска проекта указана в `STATE.md` → «Карта проекта».
  - Если доски нет — **сначала спросить Влада, может, она уже есть**, потом создать новую FigJam: скилл `figma:figma-create-new-file`, имя «<Проект> — карта проекта». Записать ссылку в `STATE.md`.
- Сначала прочитать доску через `get_figjam`. **Чужие элементы (не из наших секций) не трогать.**

## 2. Язык

**Всё на русском.** Ивритское название экрана — только в скобках, если помогает сверке со спекой. На экранах в Figma, наоборот, всё на иврите — это не путать.

## 3. Раскладка доски

- **Заголовок** над картой: «<Проект> — карта экранов (<этап>)» + легенда.
- **Раздел на роль и платформу:** секция FigJam. Первым — главный пользователь. Потом второстепенные роли. Отдельно — «Системные экраны — открываются с любого экрана».
- **Внутри раздела — зоны по навигации:**
  - вход (сплэш, вход, OTP) — левая колонка;
  - главная;
  - дальше разделы таббара / меню колонками, уровни идут вглубь вправо.
- **Строка текста под заголовком раздела:** структура навигации (таббар / меню, шапка, какие есть пуши).
- **Справка** (жизненные циклы и прочие схемы) — **сбоку**, далеко от карты (≈ x + 9000). Основное место — под карту экранов.

## 4. Карточка экрана

Широкий стикер (`isWideWidth = true`), размер шрифта 18, автор скрыт.

```
№<N> · <НАЗВАНИЕ ЗАГЛАВНЫМИ> · <P1–P5> · <метки>
Что: <зачем экран пользователю>
Инфо: <какую информацию даёт, через « · », без порядка важности>
Вход: <как попасть>
Ведёт: <куда>            (можно опустить, если всё показано стрелками)
Назад: <куда>            (если не очевидно: пуш, глобальный экран)
Состояния: <загрузка · пусто · ошибка · доменные>
```

**Метки в первой строке:**
- `+ добавлен` — экрана нет в спеке;
- `⚠ спека ссылается, экрана нет`;
- `✓ решено: …` — решение Влада;
- форма, если не экран: `sheet` / `диалог` / `панель`.

**Цвет стикера = приоритет** (палитра FigJam, hex/255):

| Приоритет | Цвет | Hex |
|---|---|---|
| P1 якорь | оранжевый | `#FFD3A8` |
| P2 вход | фиолетовый | `#D3BDFF` |
| P3 основные | зелёный | `#B3EFBD` |
| P4 второстепенные роли | бирюзовый | `#B3F4EF` |
| P5 системные | серый | `#E6E6E6` |
| внешний узел | белый | `#FFFFFF` |

## 5. Стрелки

- Коннектор `ELBOWED`, стрелка на конце, серый `#757575`. Стрелка = путь «откуда → куда».
- **Путь предложен командой, в спеке его нет** — красный `#FF7556` + пунктир `dashPattern [10, 10]`.
- Рисовать **основные** пути. «Назад» стрелками не рисовать — его описывает карточка или таблица навигации.
- Стрелки внутри раздела — дочерние элементы секции.

## 6. Раскладка — двухпроходная

1. Создать все стикеры раздела, задать текст и цвет.
2. Прочитать реальную высоту каждого стикера. Высота строки = максимум по строке. Расставить по сетке: колонка = 416 + 110, отступ между строками 90.
3. Подогнать размер секции под содержимое (+40 по краям).

Не больше ~25 стикеров за один вызов `use_figma`. Большие разделы — в несколько вызовов. Возвращать id созданных узлов.

## 7. Обновление после ответов Влада

- **Править на месте:** менять текст и цвет существующих карточек, а не перерисовывать карту.
- Решённое помечать `✓ решено: …`, снимать `⚠` и `?`.
- Новый экран — новый стикер рядом с родственными + стрелки.
- Слитый экран — удалить стикер, его содержимое перенести в карточку родителя.
- После обновления — скриншот раздела и проверка: текст не обрезан, стикеры не перекрываются.


## 6a. Уроки первого прогона (агент нарисовал чистовик Mayors)

- **Ширина.** «Зоны колонками, уровни вправо» даёт доску ~7 тыс. px. Зоны с глубиной ≤ 2 ставь **друг под другом** (зона = строка), а колонками — только уровни. Цель: ширина раздела ≤ ~4 тыс. px.
- **Стрелки сквозь стикеры.** ELBOWED сам прокладывает путь через стикеры. Задавай магниты явно: вглубь — RIGHT → LEFT, внутри зоны — BOTTOM → TOP. Если стрелка всё равно режет карточки — убери её и оставь путь в строке «Вход» карточки.
- **Строка «Назад»** — добавить в карточку (после «Ведёт»), если «назад» не очевиден (пуш, глобальный экран).
- **Экран на двух уровнях** (в него входят с разной глубины) — одна карточка, на её «главном» уровне. Другие входы — в строке «Вход».
- **Экран, общий для ролей** — одна карточка в общей секции ролей, различия прав — строкой «Права: …».
- **Пуши** — отдельный стикер-таблица «Пуши» в углу раздела: событие → экран → «назад». Не в строке под заголовком.
- **Подформы** (sheet загрузки, панель проверки) — строкой «Подформы: …» в карточке родителя, не отдельными стикерами.

## 6b. Уроки обновления карты (30.09, пачка «объект и сделка» v5; ✓ Влад)

- **Шрифт стикера смешанный** (первая строка Inter Bold, остальное Inter Medium): `loadFontAsync(text.fontName)` падает на `figma.mixed`. Грузить **оба** начертания, после записи текста ставить шрифт по диапазонам.
- **Конец коннектора:** `position` — **в пикселях относительно узла**, не доли 0–1 (доли дают угол стикера). Пиксели позволяют развести две стрелки на одной стороне.
- **ELBOWED с общим концом** сливает две стрелки в один отрезок. Для циклов справки — STRAIGHT с разными точками крепления; встречные переходы — двумя параллельными линиями.
- **Карточка выросла от правки** → сдвинуть соседей ниже в той же колонке и заново подогнать секцию; проверка перекрытий — после каждого роста.
- **Длинные стрелки через всю карту** (в модальные потоки, глобальные экраны) не рисовать — писать в строку «Вход» (подтверждено).
- **Новый статус или цвет** ([В] и т. п.) — сначала дописать легенду, потом ставить.
- **`node.clone()` в FigJam** кладёт копию в корень страницы, а не в секцию оригинала → после клона `section.appendChild(copy)`, потом координаты.
- **Скриншот из облачной сессии:** `curl` к figma.com режется прокси → только `get_screenshot` с `enableBase64Response: true` (≈ до 2400 px); мелочи сверять по рамкам коннекторов (x, y, width, height).

## 8. Типичные провалы

- Текст на иврите или английском вместо русского.
- Перерисована вся карта вместо правки на месте — теряются правки Влада.
- Тронуты чужие элементы доски.
- Стрелки-спагетти: нарисованы все «назад» и второстепенные пути.
- Цвет не по приоритету.
- Справка лежит посреди карты.
