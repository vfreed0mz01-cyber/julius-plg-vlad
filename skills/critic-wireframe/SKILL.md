# Критик экрана

> v1 (2026-10-23) — коротко; откуда каждое правило, цитаты — `log.md`. Правило без способа проверить — не правило.

## 1. Когда, кто, вход
После сборщика и до показа Владу — всегда. **Отдельный агент**, не тот, кто решал или строил. До проходов 1–2 читает только «Зачем пришёл» и «Содержание и ранги» — не лейаут, не решения, не аннотации. Логику до сборки проверяет `critic-logic`; этот — работает ли нарисованное.
Вход: скриншоты через `node.screenshot()` (`shared-wireframe-kit` §3 п. 6), общий план и зоны крупно, аннотации не снимать · `shared-ux-principles` §2–§3 · после прохода 3 — лист целиком, таблица паттернов, `navigation.md` («было → стало»).

## 2. Проходы
1. **5 секунд (вслепую).** До чтения листа: что за экран · что главное · куда нажать · что прочитал последним перед кнопкой. Не совпало с «Зачем пришёл» и рангами — находка, даже если чек-лист чист. Второй вопрос — с **основного входа** (не из пуша): «зачем я открыл экран и нужно ли что-то сделать?» — не читается за 5 с, а действия лежат внутри длинной структуры (ось, список) одним весом с контекстом → находка «перегружен / непонятна цель».
2. **Сценарии (вслепую).** На каждый вход: путь глаза, шаги до цели, где можно ошибиться (деньги). Шаги по кадрам сверить с «было → стало» в `navigation.md`: больше записанного или больше «было» без причины → находка.
3. **Чек-лист §5** — каждое нарушение находка.
4. **Сверка с листом.** Только теперь: намерение из прохода 1 = намерение листа · «экран ≠ лист» — ошибка сборки (чинить) или решения (вернуть проектировщику через лида) · обоснования листа не спорят с видимым.

## 3. Формат находки
«Плохо / некрасиво / скучно» без принципа и места не пишется.
```
### Находка N — <зона / элемент>
- Что видно: … · Принцип: P… — как нарушен · Что случится у пользователя: …
- Серьёзность: блокирует / мешает / мелочь · Исправление: … · кто: сборщик / проектировщик
```
Сборку (обрезка, отступ, выравнивание, сетка) чинить сразу, повторить скриншот и проверку; решение — вернуть проектировщику с предложением. Только потом — Владу.

## 4. Формат выхода
`04-critic/<№>-screen.md`: ответы прохода 1, путь глаза прохода 2, находки (§3), что исправлено, что вернули. Новое правило от Влада → строка в §5, цитата и дата — в `log.md`; не ложится ни в один принцип → предложить принцип в `shared-ux-principles`.

## 5. Чек-лист
Принципы — `shared-ux-principles` §2, не пересказываются. «Где» — применять только там, где действует причина правила; пусто = везде.

| P | Правило · где | Как проверить |
|---|---|---|
| P1 | Итог и сумма у кнопки, не сверху · подтверждение и оплата, не обзор | Последнее прочитанное перед кнопкой — итог |
| P2 | Ранг 1 в начале чтения · обзор | Первое справа сверху = ранг 1 из листа |
| P3 | В блоке одна точка фокуса | Сильных элементов (чип, ссылка, заголовок, сумма, кнопка) в блоке < 3 |
| P3 | Карточка ранга 1 = фокус + одно действие · карточки-задачи на обзоре | Метаданные одной строкой; нет чипов статуса и вторичных ссылок |
| P3 | Одно крупное число в первом экране · числа разного смысла на виду | Крупных чисел разного смысла ≤ 1; место числа решает P1 / P2 |
| P3 | ≤ 3 уровней текста в блоке | подпись → значение → пояснение |
| P4 | Сирот нет; внутри группы теснее, чем между; группы — воздухом | У каждого элемента зона; `gap/in-group` < `gap/between-groups`; заливка ≤ 1 блока ранга 1; текст от линии ≥ 16 |
| P4 | Деньги и навигация не в одном блоке · блоки показателей | В блоке с суммой нет ссылки-перехода |
| P5 | Однотипные значения одной структуры | Подпись над значением у всех; стили и колонки равны |
| P6 | Колоночная сетка проекта · все кадры и варианты | Кодом `frame.layoutGrids.length ≥ 1`, поля и промежуток — переменными |
| P6 | Одна вертикаль начала текста, RTL — правая | Кнопки-ссылки на той же вертикали |
| P6 | Короткий статус по центру, длинное — к правому краю · результат, успех, ошибка, пусто, загрузка | Значок, заголовок, текст, спиннер центрированы; таблицы / списки / формы справа |
| P7 / P8 | Главное действие одно, зона по норме платформы (≥ 44 pt), в зоне пальца; таббар не дублируется ссылками в контенте (корни вкладок) | Нижняя треть или липкая панель; второй равноправной кнопки нет; нет ссылки на раздел, который уже во вкладке |
| P11 | Выход и главное действие на одних местах · шаги одного потока | Координаты кнопки и выхода совпадают между кадрами |
| P18 | Шаг не повторяет виденное на прошлом · особенно результат | На результате только новое: статус и что дальше; «чека» нет |
| P13 | Статус словом + значком, «что дальше» сказано; символ не приклеен к слову («מושכר ✓», «● בבנייה», «!» в строке) · вайрфрейм и дизайн | Статус читается без цвета и стоит отдельным элементом, не символом в тексте |
| P14 | Деньги защищены · деньги | Подтверждение есть; опасное не рядом с главным |
| P15 / P16 | Кегль и зоны из параметров, подписи у нестандартных иконок; ранг 1 и главное действие выше сгиба | Основной ≥ параметра, зоны ≥ `size/touch`; линия первого экрана отмечена, ранг 1 целиком над ней |
| P17 | Короткий экран не приклеен к верху · результат, пусто, ошибка, успех | Нет пустой нижней половины при стопке у шапки; иначе меньше форма или блок в оптический центр / к действию |
| P17 | Верх кадра (300–400 px) — одна композиция · любые экраны | Герой или группа, не 3+ одинаковых блока подряд (значок · заголовок · текст · таблица) |
| P19 | Каждый блок обоснован строкой листа | Блок без строки — лишний |
| Каркас | Корень вкладки без названия страницы в шапке (уровни 2–3 и модальные — с заголовком); в шапке только нужные действия, расположение по STATE | Заголовка нет на корне; шапка совпадает с решением проекта |
| Техника | Ничего не обрезано; FILL / HUG верны; иврит без `<…>`; отступы переменными; имена английские | Крупный скриншот + обход узлов (`shared-wireframe-kit` §3) |
