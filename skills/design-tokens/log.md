# Токены

> v0 (2026-09-30). Записан по обсуждению с Владом (команда Дизайна ✓ 30.09: токенист и сборщик DS — два агента, чтобы значения не подгонялись под «проще собрать»; блок-лист дефолтных палитр ✓). Урок старого пака 1.0.6: палитра садилась на стоковые hex (Tailwind-синий, Bootstrap-статусы), радиусы и отступы — на дефолты фреймворка.

## 1. Когда и кто
- После остановки ② (стиль, цвет, шрифты, иконки, радиусы — ✓ Влада в STATE) и утверждённых вайрфреймов.
- Агент `tokenist`. Строит **только значения** и их обоснование; в Figma не пишет.
- **Пилотом:** сначала только токены, нужные одному экрану (у Mayors — №1 главная), потом расширять по пачкам. Токен без места употребления не заводим.

## 2. Вход
STATE (решения Влада — закон: бренд, фон, шрифты, радиусы, иконки, тон «нужно действие»), параметры вайрфреймов (сетка, шкала отступов, кегли, зоны нажатия), `02-research/visual/color-type.md` (раздел «Что передаём Дизайну»), `refs.md` (приёмы с замерами), `assets.md` (иконки, образы), `pilot-status.md` (система статусов), бриф (регистр, 50+, RTL), кадры экрана-пилота и его лист решений.

## 3. Источник у каждого значения
Каждый токен — `value` + `source` + `use` (где стоит). Допустимые источники:
- **замер** рефа (ID из `refs.md` / `color-type.md`: «С1-4 кнопка 12.75:1»);
- **бренд** заказчика (hex из STATE) или наш бренд из `03-design/brand.md` (этап Бренда, решения Влада Б1–Б3);
- **решение Влада** (строка STATE);
- **вывод** из другого токена по правилу (шаг OKLCH-шкалы, пол AA, +1–2 px для 50+) — с названием правила;
- **параметр вайрфреймов** (STATE).
Запрещены: «из памяти», генераторы палитр (Colormind и т. п. — это медиана), библиотеки (Tailwind / Material / Bootstrap / Radix / Open Color), чистые 100 %-насыщенные hex, «голый» серый без подмеса оттенка мира (подмес — от бренда или замера фона рефов).

## 4. Слои
1. **Примитивы цвета** — шкалы в OKLCH вокруг якорей (бренд, тёплый тон, нейтраль с подмесом). Шаг по L, C снижается к краям. Утилиты: `tokens_check.py --oklch HEX`, `--hex L C H`.
2. **Семантика цвета** — роли, не оттенки: `surface/page`, `surface/raised`, `surface/sunken`, `ink/1–3`, `line/hair`, `line/strong`, `accent/fill`, `accent/on`, `accent/wash`, статусы по семьям из STATE (`status/action`, `status/waiting`, `status/done`, `status/progress` — у каждой `ink` и `wash`), `meter/fill` ≠ `meter/track`, `focus`. Статусы ≠ хром; акцент не расползается в хром (60-30-10 — ориентир). Цвет — не единственный носитель (форма / слово рядом); для «выбрано» достаточно заливки с разницей по светлоте ≥ 3:1 к невыбранному — галочку поверх не добавлять (Влад 04.10).
3. **Шрифт** — роли (`display`, `title`, `heading`, `body`, `body-strong`, `label`, `caption`, `amount-l`, `amount-m`) → семейство по письменности (иврит / латиница и ₪ / цифры), размер, высота строки, вес, трекинг. Пол 50+: основной ≥ 17. Недостающие глифы основного шрифта — роль партнёра явно (у Mayors: Julius без латиницы, ₪, `/ · – … ׳ ״` → Inter ×0.897).
4. **Отступы** — из параметров вайрфреймов (шкала, внутри / между групп, поля сетки); новые значения — только с причиной.
5. **Радиусы** — по решению Влада (у Mayors 0–4, пилюля только у главной кнопки оплаты).
6. **Иконки** — набор, размеры по контексту (строка / таббар / кнопка), штрих ↔ вес шрифта (замер из `assets.md`).
7. **Прочее по необходимости** — тени (обычно нет), прозрачности как именованные wash, толщина линий.
8. **Материалы — только если в паспорте направления глубина «со слоями»** (✓ Влад 03.10; «не для каждого проекта»). Материал — именованный рецепт поверхности, а не одно значение: `material/<имя>` = `fills` (список по порядку снизу вверх: база, свет, затемнение) + `stroke` + `effects` (внутренние тени, одна внешняя) + `light` (откуда свет) + `source` (строка «слои поверхности» из разбора рефа) + `use`. На продукт 2–3 материала, один источник света. Цвета слоёв — из примитивов; прозрачности — числом. Для текста на материале завести пару `check/*` по худшей точке материала. `tokens_check.py` слои не проверяет — проверяет критик глазами рядом с рефом.

## 5. Пары контраста
В `pairs` — каждая пара «текст / значок / граница на поверхности», которая реально встречается на экране-пилоте: `text` 4.5 · `large` (≥ 24 или ≥ 19 bold) 3 · `ui` (значки, границы полей, полосы) 3. AA — пол, AAA не требуем. Бледный текст из рефа берём стилем, контраст чиним значением.

## 6. Выход
- `03-design/tokens.json` — машинный (формат — в шапке `tokens_check.py`).
- `03-design/tokens.md` — для людей: таблицы по слоям (токен · значение · источник · где), шкалы образцами, «развилки» (2–3 варианта + рекомендация с причиной) — только равноценные вкусовые; всё, что вытекает из решений Влада, решаем сами с пометкой [В].
- `03-design/tokens-preview.png` — образцы: шкалы, роли на поверхностях, шрифтовая шкала на иврите с суммами в ₪ (Chrome headless, как доски Ресерча). Владу показываем картинкой, не таблицей.
- Прогон `python3 tokens_check.py 03-design/tokens.json` → «LINT: чисто» — условие сдачи.

## 7. Границы
- Не меняет решения Влада и вайрфреймы; конфликт токена с решением → в развилки.
- Не собирает Figma, не рисует экраны.
- Не добавляет токен «на будущее».

## 8. Типичные провалы
- Палитра из библиотеки или «приятная» из памяти → STOCK / нет источника.
- Акцент в роли цвета текста ключевых чисел (у Mayors #063168 рядом с чернилами 1.34:1 — нельзя, STATE).
- `meter/fill` = акцент, а `meter/track` = серый фона → остаток сливается с поверхностью.
- Роли названы оттенками (`blue-500`) → семантики нет, дизайнер экрана не знает, что брать.
- Направление «со слоями», а поверхность записана одним цветом («стекло = белый 10 %») → сборщик соберёт плоско. Стекло, глубокая кнопка, светящаяся плитка — всегда рецепт из нескольких слоёв.
- 50+ понято как «огромный шрифт и ЧБ» — нет: +1–2 px и AA (STATE).
