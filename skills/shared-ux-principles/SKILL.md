# Принципы P1–P20

## 1. Три уровня доказательства
1. **Принцип** (таблица ниже) — почему это работает у людей.
2. **Конвенция** — как решают продукты **того же типа задачи** (таблица паттернов `research-patterns`, «7 из 9»).
3. **Ограничения проекта** — STATE (решения Влада ✓), бриф, аудитория, RTL.

Обоснование опирается минимум на два уровня. Решение против большинства рефов — только с причиной из уровня 1 или 3, и оно автоматически «спорное» (`critic-logic`).

## 2. Таблица
| Код | Правило | Как проверить |
|---|---|---|
| **P1** Порядок решения | На экране действия зоны идут в порядке решения: что → кому → сколько → действие; итог у кнопки | Последнее прочитанное перед нажатием — то, что нужно для решения, и оно рядом с кнопкой |
| **P2** Порядок чтения | На экране обзора ранг 1 — в начале чтения (RTL: справа сверху) | Первое, на что падает взгляд, — ранг 1 |
| **P3** Одна точка фокуса | Один доминирующий элемент на экран и на блок | Тест 5 с: все называют одно «главное»; инвентарь `heroes ≤ 1`, `primary_buttons ≤ 1` |
| **P4** Близость | Внутри группы отступ меньше, чем между группами; связанное рядом | Число: `gap внутри группы < gap между группами`; группы читаются без текста |
| **P5** Сходство | Однотипное — одной структуры и стиля | Два однотипных значения оформлены одинаково; одна форма на сущность |
| **P6** Сетка и линия | Колоночная сетка проекта; одна вертикаль начала текста | `layoutGrids.length ≥ 1` у кадра; нет узлов вне колонок |
| **P7** Фиттс | Главное действие крупное и в зоне большого пальца | Зона по норме платформы (≥ 44 pt iOS / 48 dp Android); главное действие в нижней трети или в липкой панели |
| **P8** Хик | Одно главное действие в точке решения | Равноправных кнопок в точке решения — одна |
| **P9** Узнавание | Нужное для решения — на этом экране | Решение принимается без памяти о прошлом экране |
| **P10** Конвенции | Как большинство продуктов того же типа задачи; отход — с причиной | Совпадает с большинством в таблице паттернов, иначе причина записана |
| **P11** Согласованность потока | Выход, главное действие, данные — на одних местах на всех шагах | Палец и глаз находят то же место на следующем шаге |
| **P12** Прогрессивное раскрытие | Ранг 3 — за тапом / раскрытием | На первом экране нет того, что нужно редко |
| **P13** Видимость статуса | Статус словом + значком, не только цветом; «что дальше» | После действия понятно, что случилось и что будет |
| **P14** Предотвращение ошибок | Подтверждение перед деньгами; защита от двойного тапа; опасное не рядом с главным | Нельзя случайно заплатить дважды / не туда |
| **P15** 50+ = понятность (✓ Влад 07.11: не крупнее шрифт и зоны) | Действие названо словом с результатом; нестандартная иконка — с подписью; знакомые паттерны платформы, без экспериментальной навигации; скрытое (свайп, долгое нажатие) дублируется видимой кнопкой; видно, что нажимается; после действия ясно, что произошло и что дальше; простой язык, числа с единицами. Размеры — нормы платформы (iOS HIG: текст по шкале Dynamic Type, зона ≥ 44 pt; Android: ≥ 48 dp; AA 4.5 / 3), не увеличенные | Тест: человек без опыта отвечает «что это, что нажать, что будет» без подсказки; иконок без подписи вне общеизвестных (поиск, чат, профиль) — 0; «назад» — словом + шеврон; жестов без кнопки — 0 |
| **P16** Первый экран | Ранг 1 и главное действие в бюджете первого экрана | Бюджет посчитан; ранг 1 целиком выше сгиба |
| **P17** Композиция и пустота | Пустота — решение: мало содержания → меньше форма (sheet, попап) или группа в оптическом центре с опорой внизу | Инвентарь `void_pct`, `blank_gap` в порогах; содержимое не прилипло к верху при пустой нижней трети |
| **P18** Не повторять только что увиденное | Следующий шаг показывает новое; прежние детали — по запросу | Что пользователь видит впервые — названо; остальное обосновано |
| **P19** Один экран — один вопрос | Название экрана = вопрос; соседние вопросы — глубже или на своём экране; действие — видимым объектом | Один вопрос назван; каждый элемент, отвечающий на другой вопрос, обоснован «почему не глубже» |
| **P20** Реальный разброс данных | Компонент держит минимум и максимум реальных значений (из `model.md`) | В листе строка «мин · макс · держит / не держит» для каждого ползунка, шкалы, пилюли с числом, строки с именем |

## 3. Когда принципы спорят
- **P1 vs P2**: экран действия → P1 (итог у кнопки); экран обзора → P2 (главное в начале чтения).
- **P3 vs P9**: повтор допустим, если второй раз тише (крупно в итоге + обычным в строке).
- **P9 vs P18**: P9 — нужное было давно или на другом экране; P18 — видел только что, на прошлом шаге того же потока.
- **P10 vs ограничения проекта**: решение Влада ✓ и аудитория побеждают конвенцию — записывается явно.
- **P16 vs P4**: группу ради первого экрана не рвать; лучше целая группа ниже сгиба с видимым краем.

## 4. Формат обоснования в листе
> **Задача:** … **Принцип:** P1, P4, P7. **Доказательство:** 7 из 9 экранов подтверждения. **Если иначе:** что сломается при другом месте.

«Если иначе» пустое или «будет хуже» → решение не обосновано. Принцип не говорит того, что ему приписано (P3 «фокус» как довод, *где* стоять сумме) → находка оппонента. Рефы другого типа задачи — не доказательство.
