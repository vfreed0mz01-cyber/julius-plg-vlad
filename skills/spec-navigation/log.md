# Навигация

> Черновик v0 (2026-09-29). Правила согласованы с Владом. Раздел «Типичные провалы» пополняется из его правок.

## 1. Зачем

Лишние клики и «не найти нужное» рождаются в навигации. Здесь решается:
- где живёт каждый экран;
- как до него дойти;
- куда ведёт «назад»;
- что происходит при входе из пуша.

## 2. Вход

- `STATE.md` проекта → «Решения по проекту» — приоритет над всем.
- `inventory.md` — экраны, приоритеты, карточки (как попасть / куда ведёт — черновые).
- `forms.md` — формы, слияния, как закрывается.
- `model.md` — события и уведомления (жизненные циклы, «Уведомление?»).
- `brief.md` — главный пользователь, главное действие, главная точка входа, платформы, аудитория.

## 3. Границы

- Флоу ключевых потребностей — **внутри этого скилла** (раздел 5.7), отдельного скилла нет.
- Не решаем содержание экранов.

## 4. Что искать (чек-лист)

- [ ] **Структура для каждой роли и платформы:** таббар (мобайл) / боковое меню (веб), разделы, что в каждом.
- [ ] **Место каждого экрана:** раздел + уровень (1 — вкладка / пункт меню, 2, 3…).
- [ ] **Входы и выходы** каждого экрана — финально. Черновые из инвентаризации проверить и дополнить.
- [ ] **«Назад»** для каждого экрана.
- [ ] **Пуши и уведомления:** событие → текст (суть) → на какой экран ведёт → куда «назад».
- [ ] **Глобальные элементы:** шапка, иконки в ней, бейджи непрочитанного.
- [ ] **Вход в продукт:** куда попадает пользователь после входа, при повторном запуске, из пуша при закрытом приложении.
- [ ] **Флоу** каждой ключевой потребности главного пользователя (5.7).
- [ ] **Проверки:** нет экрана без входа · нет тупиков · главное действие главного пользователя ≤ 2 тапов от точки входа.

## 5. Как решать

### 5.1 Мобайл (правила Влада)
- **Таббар:**
  - максимум 5 вкладок;
  - **подписи у вкладок всегда** (для 50+ и вообще);
  - вкладка = раздел, в который ходят часто. Редкое — не во вкладку.
- **Глубина** от вкладки — не больше 3 уровней. **Исключение (Влад, 30.09, Mayors №11):** осознанное углубление за подробностями — ок и на 4-м уровне. Пример: «Шаги покупки» показывают шаги и где мы сейчас; кто хочет подробностей шага и что от него требуется — заходит глубже. Ограничение ≤ 3 — для основных разделов и путей к главным действиям, не для «подробнее о…».
- **«Назад»:**
  - всегда есть и ведёт туда, откуда пришёл;
  - **если пришёл из пуша — «назад» ведёт на главную** (или на родителя экрана внутри раздела, если это понятнее).
- **RTL:**
  - стрелка «назад» смотрит **вправо**;
  - порядок вкладок идёт **справа налево** — первая вкладка (главная) справа.

### 5.2 Веб (рабочие роли)
- **Боковое меню** со списком разделов, с подписями (решение Влада). В RTL — **справа**.
- Детали из списка — боковая панель (см. `forms.md`), сложное — страница.
- После входа — главная своей роли.

### 5.3 Пуши
Для каждого события из модели, помеченного «Уведомление? — да», и из решений проекта:
- **экран-цель** — экран, где сразу понятно, что делать;
- **«назад»** — по правилу 5.1;
- **если цель удалена** — экран «контент не найден».

### 5.4 Шапка
Что в шапке каждого уровня: заголовок, «назад», глобальные иконки (уведомления, чат), бейджи. Глобальные иконки — только на экранах 1-го уровня, если в решениях проекта не сказано иное.


### 5.5 Что не считается уровнем
- **Модальный поток** (подтверждение → внешний шлюз → результат), sheet, боковые панели, диалоги, полноэкранный просмотр медиа.
- **Глобальные экраны** (чат, центр уведомлений) — открываются поверх из любой глубины.
Глубина ≤ 3 считается только по экранам, которые лежат «в стопке» раздела.

### 5.6 Действие ≠ раздел
«Новый X» (создать апдейт, новый чат) — это **кнопка** в разделе, а не пункт меню. Пункт меню — раздел со списком (например, «Апдейты» = история отправленных + кнопка «Новый апдейт»).


### 5.7 Флоу ключевых потребностей (влито в навигацию, решение Влада)
Для **каждой ключевой потребности главного пользователя** из брифа (и 1–2 главных задач каждой второстепенной роли):
- **Вход:** откуда пользователь начинает — пуш, иконка приложения, главная.
- **Шаги:** экран → действие → экран… Каждый шаг — что пользователь видит и что делает.
- **Клики:** сколько тапов до цели. Сравнить с **кратчайшим возможным путём** — каждый лишний шаг должен иметь причину (подтверждение денег, выбор).
- **Главная задача — «было → стало»** (✓ Влад 06.10): для главной потребности главного пользователя записать, сколько шагов было (текущий продукт заказчика или лучший конкурент) и сколько стало. Это число идёт в Case и проверяется критиком экрана.
- **Ветки:**
  - ошибка (нет сети, не прошло);
  - отмена;
  - прерывание посередине (закрыл приложение — где продолжит);
  - первый раз против повторного.
- **Выход:** где пользователь оказывается в конце и понимает ли он, что всё получилось.

Если флоу вскрывает недостающий экран или состояние — это находка: записать в «Вопросы / находки» и предложить решение (правило «сначала реши сам»).

## Правило «сначала реши сам» (Влад, 29.09)

Прежде чем выносить вопрос Владу — **реши сам, как сеньор-дизайнер**:
1. Сформулируй 2–3 варианта.
2. Выбери один с обоснованием: логика продукта + аудитория + 1–2 рефа из Mobbin (с разбором «почему так»).
3. Запиши как решение с меткой [В] и строкой «почему».

Вопросом Владу выносится только:

## 7. Типичные провалы

- Вкладки без подписей или больше 5 вкладок.
- Редкий раздел вынесен во вкладку, а частый спрятан.
- Экран глубже 3 уровней.
- «Назад» после пуша выкидывает из приложения или ведёт непонятно куда.
- Пуш ведёт на общий список, а не на конкретный объект.
- Экран без входа или тупик без выхода.
- В RTL стрелка «назад» смотрит влево, а таббар не отзеркален.
- Глобальные иконки дублируются на каждом уровне без нужды.
