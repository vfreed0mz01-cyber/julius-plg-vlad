# Стиль (В2)

Поиск, источники, картинки — `shared-research-howto`. Словарь стилей — `styles.md` рядом. История — `log.md`.

## 1. Что это
Регистр (из `spec-product-frame`) — тон, он задаёт **коридор**; стиль — визуальный язык внутри коридора (один регистр допускает ≥ 2 стилей). Стиль выбирается **до** блоков, иначе рефы блоков тянут в разные стороны. Остановка ① Влада — только стиль.

## 2. Вход
- `01-spec/brief.md` → «Рамка стиля»: регистр, зоны, признаки тона, модификаторы (50+, RTL), «нельзя», бренд заказчика (его цвета и шрифты приоритетнее).
- `STATE.md` — решения Влада ✓, шрифт проекта, что уже выбрано. `03-design/brand.md`, если был этап Бренда — стиль не спорит со знаком и цветом.
- `02-research/niche.md` → «Вид ниши» (общее место, где отличиться, антипримеры) и вывод «какой визуал подходит аудитории».
- `01-spec/model.md` — есть ли контент под стиль (фото / рендеры / карты, длина строк, крупные числа).
- `02-research/visual/plan.md` — если есть (не обязателен).

## 3. Паспорт рефа — 9 осей
Для каждого экрана-кандидата и для базового стиля после выбора. Числа — pt по оригиналу (`image_url`, @3x ÷ 3); оценка — «≈».

| # | Ось | Что записать (с числами) |
|---|---|---|
| 1 | Чем отделены группы | воздух / волосяные линии (толщина, цвет) / заливки-карточки (фон vs карточка) / тени (мягкие, резкие) / обводки |
| 2 | Радиусы | карточки, кнопки, чипы, поля; пилюля или нет; единая шкала или разнобой |
| 3 | Фон и нейтрали | фон (hex, тёплый / холодный / чистый), число нейтралей, светлая / тёмная тема |
| 4 | Где живёт цвет | в UI / в контенте (фото) / только в данных и статусах; насыщенность; **число акцентов** |
| 5 | Типографика | класс гарнитуры (геометрический / гуманистический / нео-гротеск; антиква; моно), контраст шкалы (например 34/17 = 2.0), вес заголовков, число весов |
| 6 | Плотность | отступ между группами (pt), поля экрана, строк на первом экране |
| 7 | Образы | нет / фото контента / рендеры / иллюстрации / 3D / лица; размер и обработка |
| 8 | Иконки | контур / заливка, толщина штриха, концы, в подложке или нет, с подписью или нет |
| 9 | Композиция | колонка / сетка / bento / асимметрия; выравнивание; где крупное; сколько героев |

Проверка паспорта: в каждой из 9 строк есть число или hex; строка из одних прилагательных — не заполнена.

## 4. Шаги
1. **Коридор.** Из брифа: регистр, модификаторы, «нельзя» — одной строкой каждое. Регистр сверить со STATE (расхождение → лиду). По `styles.md` каждый стиль: в коридоре ✅ / с оговоркой ⚠ / нет ❌ — с причиной. Проверка: в коридоре ≥ 2 стилей; один — коридор слишком узок, пересмотреть причины.
2. **Ниша.** Из «Вида ниши»: где совпасть (конвенции доверия), где отличиться (общее место). Кандидат, повторяющий общее место ниши, — только с записанной причиной.
3. **Контент.** Хватит ли под стиль: фото / рендеры (editorial, тёмный люкс), числа (строгий), иллюстрации (яркий). Нет контента → стиль не кандидат или с условием «нужны фото от заказчика» (бизнес-вопрос Владу).
4. **Кандидаты 2–3** из разных строк словаря (проверка: три кандидата — три разных строки `styles.md`). Для каждого 4–6 **целых экранов живых продуктов из любой ниши** (стиль ищется не в нише; лучший улов — ниша-соседка с тем же регистром: для тихого премиума — отели, премиум-путешествия, частный банкинг), платформа совпадает, среди них **≥ 1 экран без фото**. Mobbin: `search_screens` в `deep`, запрос признаками по осям паспорта или продукт-эталон. **Плюс Pinterest / Dribbble / Behance — обязательно** (✓ Влад 22.11): у каждого кандидата ≥ 2 живых экрана, остальные могут быть концептами с пометкой; хотя бы один кандидат опирается на концепты сильнее Mobbin. Выход без Pinterest — только со строкой «Pinterest не смотрели: почему».
5. **Паспорт** каждого экрана (§3) + сводный паспорт кандидата (общее у 4–6 экранов — это и есть стиль). У каждого экрана — вердикт одной строкой: брать | идея | настроение — что берём.
6. **По кандидату**: почему подходит (регистр + ниша + контент) · главный риск · наш якорный экран в этом стиле (1 строка с числами) · **без образов** (1 строка: во что превращается стиль на экране без фото; если разваливается — это риск) · иврит (чем заменить антикву / капитель: гротеск, контраст размера и веса).
7. **Рекомендация** — один кандидат с причиной. У остальных риски и плюсы записаны по той же схеме (проверка: у каждого кандидата заполнены все поля п. 6, не только у рекомендованного).
8. **Доска**: секции 0 и 1 (`research-visual-board`) → остановка ①. Владу — только стиль, ни блоков, ни иконок.
9. **После ответа Влада**: выбор → STATE (лид); в `style.md` раздел «Базовый стиль ✓» со сводным паспортом — вход для В3–В6 и правило цельности.

## 5. Формат выхода
Файл `02-research/visual/style.md`:
```
# Стиль: <проект>
## Коридор
Регистр … · модификаторы … · нельзя … · бренд заказчика …
| Стиль | В коридоре? | Почему |
## Ниша: совпасть / отличиться
## Контент под стиль
## Кандидат С1 — <стиль>
Почему подходит · главный риск · наш якорный экран (1 строка) · без образов (1 строка) · иврит
Сводный паспорт (9 осей)
### С1-1 <продукт · экран> — <mobbin_url> · живой
| Ось | Факт (числа) |
Вердикт: брать | идея | настроение — что берём (1 строка)
… (4–6 экранов)
## Кандидат С2 … / С3 …
## Рекомендация
## Базовый стиль ✓ (после ответа Влада)
Выбор Влада (дата, его словами) · сводный паспорт · что из других кандидатов можно взять в токенах
```

> **Реф стиля выбирает только Влад** (✓ 22.11): агент и лид никогда не выбирают донора стиля сами, даже «по его вкусу»; без ответа Влада дизайн экрана не начинается.
