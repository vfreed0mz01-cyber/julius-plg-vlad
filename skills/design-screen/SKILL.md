# Дизайн экрана

> v1 (2026-10-23) — коротко; история, цитаты, уроки — `log.md`. Правило = действие + как проверить.

## 1. Вход
Утверждённые кадры вайрфрейма (id из STATE) и лист экрана («Зачем пришёл», ранги) · `tokens.md`, `components.md`, `bible.md` (если есть) · `refs.md` (приёмы с замерами, строки «Принцип»), `assets.md` · STATE (паспорт направления, образ заказчика, семьи статусов, решения Влада) · задание (профиль плотности, паспорт). Сначала `shared-taste` §0 / §0а / §2; `screen-composition`; `screen-inventory`; `figma-use`.

## 2. Порядок (на экран)
0. **Два рефа и режим** (✓ Влад 22.11, тест «ארון» — «ахуенчик»; провалы дня — когда донора выбирал агент, ход придумывали, воздух сжимали).
   - **Реф стиля** — язык: шрифт и шкала, палитра и роли, поверхности, радиусы, тени, кнопки и чипы, иконки, плотность. **Выбирает Влад** (остановка стиля, доска с Pinterest — `research-visual-style`). Агент и лид реф стиля **не выбирают никогда**, даже «по вкусу Влада»; нет выбора Влада → стоп, лиду.
   - **Реф лейаута** — что наверху, порядок зон, высоты зон, где действие, плотность. Это и защита удобства (P10 конвенции): **3–5 живых экранов той же задачи** (Mobbin, продукты ниши и соседей по задаче) — из таблицы `research-patterns` этого экрана; нет таблицы — найти и записать. Порядок и высоты зон не придумываются: у каждой зоны в карте — «реф лейаута <ID> · высота у рефа · у нас».
   - **Режим** — по тому, что принёс Влад (или агент определяет и пишет почему): **А экран-донор** (задача рефа = наша: стиль и лейаут с одного экрана, 1:1); **Б доноры по блокам** (у каждого блока — донор того же типа, 1:1 внутри блока; раскладка — по рефу лейаута; все доноры одного стиля, иначе приводятся к языку рефа стиля); **В стиль + лейаут из разных рефов** (язык — от рефа стиля; компоновка — от рефа лейаута; блок, которого у рефа стиля нет, — из ближайшего по роли элемента рефа стиля, источник записать).
   - Во всех режимах: **воздух донора не сжимать** (не влезает — ниже сгиба), **мелкая типографика блоков** (пары строк, подписи, шкалы) — структурой донора, не стопкой строк; своих ходов сверх рефов нет, кроме варианта «на грани».
1. **Прочтение одной строкой**: «Читаю как: <экран> для <аудитории>, язык <…>, опора <рефы>, метафора <…>» — в заметки и в аннотацию над кадром.
2. **Карта композиции** (`screen-composition`) — файл `<экран>-composition.md`. Нет карты → кадр не рисуется.
3. **Эскизы раскладки** — 3–4 PNG / ASCII **до Figma**; один — самый далёкий от вайрфрейма. Если у заказчика есть образ «как X / не Y» — хотя бы один эскиз без каркаса вайрфрейма. Отбрасывает эскиз только Влад.
4. **Донор** (✓ Влад 07.11 / 08.11): на каждый эскиз — один экран рефа из выбранных Владом, чья задача ближе всего к задаче нашего экрана (не самый красивый). Ни один не подходит по задаче → донор по раскладке, так и записать. У трёх вариантов — **три разных донора**. Донор не может быть опорой или донором последних 3 версий этого же экрана (журнал вариантов в STATE); исключение — «намеренно: …» в записке.
5. **Реф 1:1, потом наши данные** (✓ Влад 08.11: «весь стиль полностью и лейаут с рефа, потом наши данные, лейаут немного менять, если надо»). Скрин донора подложкой 1:1 на ширину кадра (390), прозрачность 30 %, слоем `Donor — <ID рефа>`; LTR-донор для RTL-экрана — отразить (каркас зеркалится, текст и числа — нет).
   - **Переносится целиком**: лейаут (сетка, поля, высоты рядов, кадрирование, где герой и где действие) **и стиль** — палитра и её роли, характер и контраст шрифта (латиница донора → ближайший ивритский без засечек того же характера), веса, радиусы, тени и поверхности, стиль иконок, форма кнопок и чипов, приёмы.
   - **Подставляется наше**: тексты, числа, данные, фото, логотип и название — из **источника состава** (утверждённый вайрфрейм → лист экрана → последняя утверждённая версия, node id; ничего нет → стоп, лид заказывает вайрфрейм). Состав и порядок — наши.
   - **Лейаут правится минимально** — только где наш состав не ложится (другое число строк, длиннее иврит, лишний блок); каждое отступление — строкой в записке «Отступил от донора: где → почему». Блок, которого у донора нет, — в языке донора (его же формы и отступы).
   - **Приоритет при споре**: AA и нормы платформы → утверждённые бренд, шрифт и токены проекта (если есть в STATE — цвет бренда и шрифт подставляются вместо донорских, остальной стиль донора остаётся) → донор. Явный слоп в доноре (`shared-taste` §2: 18 символ-статус у слова, 22 иконки «просто вставлены» / Lucide, 24 декор вместо данных, 26 инициалы вместо фото) → правится, в записке «донор: телл N → …».
   Сначала герой и действие, потом фон. Подложку после сверки скрыть, не удалять. **Таблица перевода** в «## Дизайн»: `блок · в источнике состава · у донора · что подставлено / изменено`.
6. **Не чужое**: у донора не остаются его логотип и название, тексты, фото и данные. Стиль и приёмы донора брать **можно и нужно**. Проверка: на экране нет ни одного слова, числа и картинки донора.
   - **Донор приёма** (✓ Влад 22.11; правило — `screen-composition` §3 п. 10): у варианта «на грани» (у среднего — можно) поверх донора раскладки — **один** приём из чужой области или предмета, на блоке-ответе. Кандидаты — из `refs.md` «Доноры приёма» (нет — найти сам по глаголу пользователя и записать). Переносить правила предмета, не фактуру. Делается **пара кадров «с приёмом / без»** (PNG в `_<экран>-iterations/`) — без него не хуже → снять приём. Придумывать ход без донора нельзя.
7. **Инвентарь**: `inventory.js` → `inventory_check.py --profile <из карты> [--premium|--layered]`; таблица первой в «## Дизайн», по каждому ✗ — «починил: …» или «оправдано: <причина из задачи пользователя / STATE>» («так в рефе» — не причина).
8. **Две самоитерации**: скриншот → ✗ таблицы → линза §0а построчно с местом на экране (баланс должен быть «норм») → пять диагнозов (`shared-taste` §0) по имени: нет / был → починил → «рядом с донором» (наш экран и донор в одном масштабе, PNG в `_<экран>-iterations/`: встал бы незаметно? где хуже — числами) → поправил → ещё раз.
9. **Записка и шлагбаум**: `03-design/<экран>-handover.md` по `handover-template.md` (донор, рядом с донором, отличие от донора, что поменял, ✗ инвентаря, диагнозы, проверено, **не проверено**, где сомневаюсь) → `python ${CLAUDE_PLUGIN_ROOT}/skills/design-screen/handover_check.py <записка> --inventory <таблица .md из inventory_check --md>`. Пока скрипт не напечатал «сдача разрешена» — чинить, критику не отдавать. «Не проверено» пишется честно: пустым быть не может.
9б. **Злые данные — лёгкая проверка** (✓ Влад 23.11: «не сильно критично»; не шлагбаум): после доводки временно подставить в кадр крайние реальные значения из `model.md` / спеки — самое длинное имя / название (иврит), максимальную сумму ₪, 0 и 1 и много записей, латиницу + число в ивритской строке; скриншот `_<экран>-iterations/edge-data.png`; вернуть обычные данные. В записке одна строка «держит / не держит: где». Не держит → правка компонента или правило (обрезка, перенос, лимит), не новый кадр.
9а. **Доводка** (✓ Влад 22.11 — отдельный этап, после принятой самоитерации, до записки): кадр режется на блоки; каждый блок **3× рядом с блоком той же роли у донора** (режим А / Б — его донор; В — ближайший по роли элемент рефа стиля) → `_<экран>-iterations/polish/<блок>.png` (реф · до · после); по каждой паре — таблица числами (кегль, вес, интерлиньяж, трекинг, ступень цвета текста, поля, высоты, радиусы, толщина линий, вес иконок, тени) и правка до языка донора. Чек-лист крафта: ₪ и число одним целым и одинаково везде; табличные цифры в суммах; 3 ступени цвета текста; оптическое выравнивание иконок в кругах и кнопках; концентричные радиусы; одна вертикаль начала текста; без висячих слов; трекинг иврита 0; bidi (ник, «+₪», латиница + число) проверен глазами. Выход — `polish-before-after.png` и `vs-ref.png` (наш экран рядом с рефом стиля / набором экранов, один масштаб). Скриншоты — `node.screenshot()` в `use_figma` (серверный `get_screenshot` переворачивает иврит).
10. **Отчёт**: «## Дизайн» в листе экрана — таблица инвентаря, таблица перевода, что отличается от вайрфрейма и почему (`задача · принцип · доказательство · если иначе`), приёмы и образы, развилки — **картинкой** (эскиз А / Б). Линт: `design-components` §5 + CONTENT-VOID (низ кадра пуст > 35 %) + ORPHAN (узел в корне вне зон).

## 3. Правила
- **Вайрфрейм = что есть и в каком порядке.** Берём состав, данные, тексты, действия, порядок, зоны нажатия. Не берём форму блоков, отступы, линии, кегли, расстановку — их даёт донор (§2 п. 4–5). Менять состав / порядок — через лида к проектировщику. Образец: `examples/layout-wireframe-39.png` → `examples/layout-design-ref.png` (те же данные — другая форма: список файлов → плитки в сетке, счётчик → чип у заголовка, абзац → чеклист).
- **Только `DS/*` и токены — после того, как они есть.** До утверждения направления стиль идёт от донора (значения заводятся переменными с источником «донор <ID>»). Есть DS → нет компонента / значения → в отчёт сборщику / токенисту, не рисовать «сбоку». Ни одного hex вне переменных (инвентарь: `unbound_pct`).
- **Один герой, одно действие.** Крупное / контрастное — одно; акцент там, где действие, не в хроме. Герой может быть цифрой, не картинкой.
- **Плотность от задачи** (карта): сравнивают 5+ строк → строки / таблица; один объект → карточка / сцена.
- **Приёмы: ≤ 2 на экран, 1–2 фирменных на продукт**, повторяются системно; у каждого — принцип из `refs.md` и вопрос пользователя, на который он отвечает.
- **По умолчанию плоско.** Градиент, свечение, глянец, внутренняя тень — только если в STATE есть «глубина со слоями · реф · Влад» и у эффекта есть ответ «что сообщает / откуда свет». Громкий материал — не в повторяющейся строке.
- **Образы из контента** по слотам `assets.md`; у каждого — «что сообщает пользователю». Декор — точечно, не рядом с суммой. Фото-заглушки подписаны.
- **Нет своих фото — генерировать фото** (✓ Влад 22.11: «фотками, а не моделью»): люди и предметы под свет и фон рефа стиля (Higgsfield: люди — `soul_2`, предметы — `gpt_image_2_6`); перед генерацией — цена Владу; фото с мусорным текстом / артефактами — обрезать или перегенерировать; файлы ≤ 1400 px перед `upload_assets`.
- **Люди — живые фото**: пак `${CLAUDE_PLUGIN_ROOT}/skills/research-assets/people/` (README — подбор по возрасту / полу / региону, один свет, «голова и плечи»); нет типажа → Unsplash / Pexels; генерация — только с согласия Влада. Инициалы — только как состояние «нет фото». В шапке фото человека = «мой профиль» — вход к другому человеку делается подписанной строкой (фото + имя + роль + действие словом).
- **Премиум / строго — чек-лист наличия**: герой / основной ≥ 2,5 (мобайл; десктоп и журнальный — 4), 1 акцент, волосяные линии вместо плашек, ритм 1:2:3, один материал, число и единица на одной базовой линии. «Убрать всё» = вайрфрейм (§2 телл 28), не премиум. Серый фон + белая карточка на каждую запись — не Apple; сгруппированный список (плашка на группу) — Apple.
- **Иврит / RTL**: начало строки справа; **шеврон и стрелка — только иконкой** (`Icon/caret-left` = «вперёд» в RTL), не символом в строке; составные числа — единым LTR-прогоном; горизонтальный скролл стартует справа; проверка на максимальной длине строки; статус у слова («מושכר ✓») — запрещён.
- **Заголовок экрана и ведущие суммы — свобода** (✓ Влад 07.11): размер и вес по рефам / донору; ни обязательного Light, ни обязательного Bold.
- **Главный блок (hero)** (✓ Влад 07.11, раунд 2): один вопрос — один ответ; вторичные дела в hero не складываются. Главное действие экрана — кнопка во всю ширину под ответом (суммой).
- **Лестница действий**: главное — заливка, одно на экран · второстепенное внутри блока — пилюля с оттенком бренда · «все …» и «добавить / сообщить» — текстовой ссылкой у заголовка раздела. Одинаковые серые пилюли на все действия — телл 29.
- **Статус, который ищут** (заявка, платёж) — чип: слово + цвет семьи из STATE; серый текст — только для фактов.
- **Разделы**: заголовок раздела над плашкой (iOS inset grouped header), внутри — только записи. Шапка экрана не тяжелее hero (кегль и вес ниже ведущей суммы / заголовка hero).
- **Денежная строка** (✓ Влад 07.11) — только для **повторяющихся** строк, не для hero: подпись и срок · **сумма своей колонкой**, заметнее подписи · действие коротким глаголом («לשלם», «לבחור»). Сумма в кнопку строки не входит — только в главную кнопку экрана. Проверка: в повторяющейся строке нет кнопки с ₪.
- **Пол платформы** (✓ Влад 07.11; донор и вкус ниже не опускают): «назад» — словом + шеврон («חזרה ›»); знаки со смыслом там, где они снимают вопрос (замок у необратимого, логотип карты у способа оплаты); список однородных записей — сгруппированный (одна плашка на группу) или строками через линию, не карточка на запись.
- **50+ = понятность** (P15), не крупнее шрифт и зоны: действие словом, подписи у нестандартных иконок, видно, что нажимается, знакомые паттерны. Размеры — нормы платформы (iOS HIG: текст по шкале Dynamic Type, зона ≥ 44 pt; Android: ≥ 48 dp; AA 4.5 / 3). Не ЧБ.
- **Пол крафта**: «дорогой продукт или шаблон?» — если шаблон, искать недостающий слой (образ, ритм размеров, приём), не добавлять декор.

## 4. Варианты и направления
- На экран — **3 целых варианта**: состав, порядок, тексты одни; отличаются **карта композиции и форма блоков**, не цвет. **Один — на грани** (у потолка Л3; донор раскладки + донор приёма, §2 п. 6), один «аккуратно без приёмов», один между. Различимы за 5 с и по разнице таблиц инвентаря. Нельзя: один сильный + два соломенных; отличие в одном блоке; варианты цветом.
- **Паспорт направления** у каждого варианта: тип темы · характер шрифта · принцип структуры · образы · поверхность (плоско / со слоями) · логика палитры · 4 фирменных компонента · 2 декоративных приёма. Паспорта расходятся ≥ 3 осями.
- Пока направление не выбрано — **хотя бы один вариант вне токенов** (значения с источником-рефом, AA / 50+ / RTL обязательны). Порядок: направление → Влад выбирает → токенист выводит систему → остальные экраны.
- **Метод по рефам**: материалы (шрифт в Figma, фото ≥ 3× слота, иконки) → галерея живых экранов картинками (если заказчик назвал продукт — сначала его экраны; нет — просить скрины у Влада в первый день, без них не рисовать) → Влад выбирает 2–3 → на каждый экран донор из них: лейаут и стиль 1:1, данные наши (§2 п. 4–6); замеры (шкала, радиусы, иконки) — в библию и токены. 2 направления × 3 итерации, не 4 концепта за заход.
- **Библия приложения** (`03-design/bible.md`) — после выбора направления, до второго экрана: тип темы, шкала, ритм, отступы, радиусы, иконки, образы, навигация, карточки, кнопки, тени. Экраны 2…N меняют композицию и темп, не систему.
- **В Figma — только финал и развилки.** Итерации — PNG в `03-design/screens/_<экран>-iterations/`; старое — в `Archive`, не удалять; уменьшенных копий не делать.

## 5. Где и границы
Страница дизайна в файле вайрфреймов (имя — по решению Влада; перед созданием спросить). Кадры 390 × 844 (веб — по заданию), имена английские, экраны на иврите, аннотации по-русски. Не меняет токены, компоненты, логику экрана; себя как критик не проверяет; старые кадры не удаляет.
