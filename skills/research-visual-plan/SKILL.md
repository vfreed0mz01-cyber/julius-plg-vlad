# План визуального ресерча (В1)

Поиск, источники, картинки — `shared-research-howto`. История правил — `log.md` рядом.

## 1. Цепочка Ресерча визуального
| Шаг | Скилл | Выход |
|---|---|---|
| В1 план | `research-visual-plan` | `02-research/visual/plan.md` |
| В2 стиль | `research-visual-style` | `style.md` → остановка ① Влада (только стиль) |
| В3 + В4 рефы и приёмы | `research-visual-refs` | `refs.md`, `crops/` |
| В5 цвет и типографика | `research-visual-anatomy` | `color-type.md`, `anatomy/` |
| В6 ассеты | `research-assets` | `assets.md` |

Стиль (В2) от плана не зависит и может идти раньше (после рамки и ниши).

## 2. Вход
- `STATE.md` — решения Влада ✓; список утверждённых кадров с node id.
- Кадры в Figma (файл вайрфреймов) — состав блоков: инстансы кита `WF/*`, группы.
- Листы решений `01-spec/screens/<№>-*.md` — задача блока, ранг, главное действие, «Спорное».
- `shared-wireframe-kit` — список компонентов (дедупликация).
- `01-spec/brief.md` — регистр, модификаторы (50+, RTL), «нельзя», платформы. `02-research/niche.md` — продукты региона (RTL-источники). `01-spec/model.md` — реальный контент (длина иврита, суммы, пусто).
- Прошлый визуальный ресерч / пилот — что уже выбрано, не искать заново.

## 3. Когда запускать и градация кадров
- План пишется по **утверждённым** кадрам; дописывается после каждой утверждённой пачки.
- **✓ утверждён** → блоки в план полностью. **На проверке** (у критика / Влада, архитектура устоялась) → блоки с пометкой «vN, на проверке» в названии; искать можно параллельно, после ответа Влада сверить с принятой версией и выкинуть рефы под ушедшее. **Позже** (черновик) → только строкой.
- Проверка: каждый блок в таблице имеет одну из трёх пометок; блок без пометки — ошибка.

## 4. Правила
- **Блок** = смысловая группа экрана (карточка платежа, сводка портфеля, строка объекта, ось шагов, sheet результата), не каждый текст. Читать кадры `use_figma` (только чтение: имена детей верхнего уровня, `mainComponent.name` инстансов) или по листам. ID `Б1…Бn` по приоритету.
- **Дубли слиты по компоненту кита**: `WF/Payment card` на №1 и №7 — один блок, два экрана. Проверка: один `mainComponent.name` не встречается в двух строках таблицы.
- **Задача блока — из листа** («Содержание и ранги» / главное действие), не придумывается. Формат: «Б2 Карточка ближайшего платежа — увидеть срок и сумму и перейти к оплате; ранг 1 на №1; главное действие «לתשלום · сумма»». Нет в листе → строка «задача в листе отсутствует» лиду.
- **Запросы по функции**, не по нише: «upcoming installment card with due date and pay button», «vertical step tracker with current step expanded» — да; «dubai real estate app», «investment app card» — нет. Нишевый запрос — ≤ 1 на блок, только для RTL / региона. Проверка: в запросе названы данные и действие блока, нет названия ниши.
- **Ограничения** у каждого блока: деньги (суммы, подтверждение), RTL (направленные элементы), 50+, крайний контент (длинный иврит, 7-значные суммы, пусто), наличие фото.
- **Норма**: 3–5 рефов на блок, ≥ 2 живых от ≥ 2 продуктов. Страницы (целые экраны) 6–10 — после выбора стиля, в плане только список наших экранов. Детали 10–15 кропов, приёмы 8–12 — в плане только места и темы. За 3 запроса нет живых → «не нашлось», концептами не подменять.
- **Порядок**: блоки якорного экрана (P1), затем по частоте блока в продукте.
- **RTL-источники — заранее**: конкретные продукты региона из `niche.md`, где смотреть, время. Проверка: раздел «RTL-источники» не пуст или содержит «RTL не смотрели — причина».
- **Места для приёмов** — 2–4 блока, где необычное построение уместно (крупные, повторяющиеся, с фото), с ограничениями (RTL, длина иврита, 50+).
- **Решённое Владом** — отдельной строкой «не ищем».
