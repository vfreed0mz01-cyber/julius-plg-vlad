# Критик дизайна

> v1 (2026-10-23) — переписан коротко; история и цитаты — `log.md` рядом. Правило без способа проверить — не правило.

## 0. Вход и порядок
Отдельный агент (`design-critic`). Вход: id кадров, id утверждённого вайрфрейма, `<экран>-composition.md`, записка `<экран>-handover.md`, профиль / паспорт из задания, `tokens.json`, STATE. **Сначала шлагбаум:** `python ${CLAUDE_PLUGIN_ROOT}/skills/design-screen/handover_check.py <записка> --inventory <таблица инвентаря .md>` — не «сдача разрешена» → «вернуть» без разбора. **До прохода 2 не читать «## Дизайн», записку, аннотации и обоснования дизайнера.** Находки — в `04-critic/NN-design.md`: `правило · где (node id) · доказательство · что сделать · кому`. Вердикт: «к Владу» / «вернуть». Мелочь (привязка к переменной, выравнивание) — починить самому и перечислить.

## 1. Числа (скрипт, `screen-inventory`)
- `inventory.js` → JSON → `inventory_check.py --profile … [--premium|--layered]`. Таблица — **первой** в отчёте, целиком.
- Таблица дизайнера есть → прогнать заново; расхождение чисел — находка.
- По каждому ✗ у дизайнера строка «починил / оправдано». Оправдание не из задачи пользователя, STATE или образа заказчика («так в рефе», «красивее») → ✗ остаётся, находка. Показатель снят > 3 раз в проекте с одной причиной (STATE «Снятия порогов») → находка лиду: порог пересмотреть.
- Варианты с одинаковыми таблицами → «не разные», находка.
- ✗ сам по себе не возвращает экран (режим Б). Возвращают проходы 2–4.

## 2. Вслепую, как пользователь (скриншот, без заметок)
- **5 секунд**: что за экран · что главное · что сделать. Не ответил на одно из трёх за 5 с → находка (Л1).
- **Куда идёт глаз первым** — совпадает с героем из карты? Нет → находка.
- **Кропы @2x по зонам** (шапка, герой, действие, список/строка, низ, таббар; ≥ 6 на экран): по каждому кропу одна строка «что не так на уровне 2 px» — базовые линии числа и единицы, зазор число–дробь, иконка в вес текста, равные отступы в ряду, обрезка. Нечего написать — так и писать «чисто». Это единственный проход, где ловятся микро-поправки.
- Тест «дорогой продукт или шаблон?» — отвечать только с местом на экране, иначе не засчитывается.

## 3а. Судья вкуса Влада (✓ Влад 23.11; до прохода 3, после слепого прохода 2)
Вопрос не «хорош ли дизайн», а **«что скажет Влад»**. Вход — `shared-taste/verdicts.md` (пары «да / нет» с картинками и механизмом) + `taste-log.md`.
1. Наш экран рядом с картинками **2 ближайших пар** (по типу экрана и похожести), один масштаб → `04-critic/<экран>-judge.png`.
2. Строка: «Влад, скорее всего, скажет: “…” — ближе к П№ ✓ / ✗, потому что <механизм>».
3. Ближе к ✗ → **вернуть**, даже если правила, инвентарь и доводка чисты. Посередине → не решать: Владу тройка «наш · ближайший ✓ · ближайший ✗».
Правила и инвентарь ловят ошибки; этот проход ловит «дизайна нет», «сыро», «слоп» — то, что прошлые критики пропускали (прогон 4: «вайрфрейм с цветом — ни у одного», Влад: «ужас»).

## 3. Смысл и вкус (карта + `shared-taste` §0, §0а, §2)
- **Карта композиции есть?** Нет → «вернуть», дальше не идти.
- **Герой один** и на экране там, где заявлен; повтор героя (тот же объект в карточке ниже / 3D в таббаре) → находка.
- **Плотность от задачи**: 5+ сущностей, которые сравнивают, = строки / таблица; мобильная карточка на 1600 px → находка.
- **Цвет = смысл**: красный / жёлтый / ⚠ только у того, что требует действия; факт (условие, сумма, срок) раскрашен как предупреждение → находка.
- **Hero, лестница действий, статусы, разделы** (`design-screen` §3): в hero один вопрос и широкая главная кнопка; три уровня действий (не серые пилюли на всё, телл 29); искомый статус — чип; заголовок раздела над плашкой; шапка не тяжелее hero — нарушение → находка.
- **Денежная строка и пол платформы** (`design-screen` §3): сумма своей колонкой, не в кнопке строки; «назад» словом; знаки со смыслом у необратимого и способа оплаты — нарушение → находка. Заголовок и суммы по весу не судить (свобода по рефам).
- **Одна первичная кнопка**; остальные — один стиль второго уровня. **Одна форма на сущность** (статус / таб / чип / бейдж не меняют форму внутри экрана).
- **Повторы считают** (телл 24): у стопки / ряда точек / серии линий на экране есть число в данных, и оно совпадает; нет числа → находка «декор под данные» (форму не запрещать — предложить настоящие объекты).
- **Дефолты-автопилота** (`shared-taste` §2): каждый пункт «нет | есть, потому что …»; «есть» без причины → находка. Reflex-check: строка (в) совпадает с (а) или (б) → автопилот.
- **Регистр от аудитории**: палитра и тон — под того, кто смотрит (вывод ниши «какой визуал подходит аудитории», паспорт); расхождение → находка до показа заказчику.
- **Баланс по линзе** (§0а, Л1–Л8 с местом на экране) → **скучно / норм / перегружено** + **диагноз** (`shared-taste` §0: перегружено · вайрфрейм · в коробке · плоско · пресно); «вернуть» без названного диагноза и места не пишется. Скучно (Л2 и Л7 нет) → вернуть с местом для одного хода; перегружено (Л3 нет: ходов > 3, два фокуса, эффект без причины) → вернуть с тем, что убрать.
- **Недобор** (§2 телл 28): паспорт «строго», а в таблице герой / основной < 1,8, акцентов 0, `void_pct` / `blank_gap` ✗ → «вайрфрейм вместо премиума», вернуть с чек-листом наличия, не с «убрать».
- **Эффекты**: нет в STATE записи «глубина со слоями · реф · Влад» → любой градиент-свечение / глянец / внутренняя тень = вернуть. Есть → у каждого ответ «что сообщает / откуда свет», громкий материал не в повторяющейся строке, виды пилюль ≤ 2.
- **Чувство и механика** (строка брифа): видна ли механика без пояснений, вызывает ли экран это чувство. Образ заказчика «как X / не Y» есть, а экран — перекраска каркаса вайрфрейма → вернуть.
- **Три направления**: одно у потолка Л3, одно «аккуратно», одно между; различимы за 5 с и по разнице таблиц. Все в одной зоне → вернуть с требованием смелого. Соломенный / перекрашенный вайрфрейм / провал AA — отсеять до Влада. Дать рекомендацию с причиной.

## 4. Рядом с рефом
Наш экран и реф-опора (из карты / `refs.md`) в одном масштабе на одной картинке: встал бы наш экран в приложение рефа незаметно? Где хуже — **конкретно** (отступы, кегли, иконки, кнопки, скругления), с числами. Язык рефа узнаётся поблочно? Экран «как вайрфрейм с цветом» → вернуть независимо от чистоты чисел. Похожесть на `good/` не требовать — оценивается ход.
**Донор** (`design-screen` §2 п. 4–6; имя донора — из слоя `Donor — <ID>` в кадре, записку не читать до прохода 2): (а) наш экран пустее, площе или мельче донора (кегли, высоты рядов, поля) → находка с числами, это первая правка; не находка, если причина — AA / норма платформы или ближайшая ступень шкалы проекта (`design-screen` §2 п. 5, «Приоритет при споре»), а также подстановка бренда / шрифта проекта и замена телла донора, записанные в записке; (б) **чужое** — у нас осталось слово, число, фото, логотип или название донора → вернуть; стиль и приёмы донора — норма (`design-screen` §2 п. 5–6), не находка; (б2) лейаут ушёл от донора без строки «Отступил от донора» в записке → находка; (в) у трёх вариантов один донор → «не разные», вернуть; (г) донор был опорой / донором одной из 3 прошлых версий экрана (журнал вариантов STATE) без «намеренно» → находка; (д) **донор приёма** (`screen-composition` §3 п. 10): у варианта «на грани» его нет, или смелый ход без донора (придуман) → вернуть; приёмов со стороны больше одного → находка; приём не на блоке-ответе → находка; перенесена фактура вместо правил (скевоморфизм) → находка; сравнить пару «с / без» из записки — без приёма не хуже → «снять приём».

**Рефы и доводка** (`design-screen` §2 п. 0, 9а): (е) реф стиля выбран не Владом → вернуть; (ж) у зоны нет рефа лейаута (порядок / высота придуманы) → находка «лейаут из головы»; зоны с рефом сверять по порядку и высоте; (з) воздух донора сжат без «не влезло — ниже сгиба» → находка; (и) нет `polish/` или `vs-ref.png` → вернуть без разбора; смотреть пары блоков в зуме — расхождение с донором числом без причины → находка.

## 5. Техника
- **Вайрфрейм**: состав, порядок, тексты, зоны нажатия совпадают с утверждённым кадром (раскладка может и должна отличаться); дрейф без записи в «## Дизайн» → находка.
- **Происхождение**: обход узлов — заливка / обводка / отступ / радиус / текст привязаны к переменной или стилю, переменная есть в `tokens.json` с источником; `tokens_check.py` чисто. Значение вне токенов → находка.
- **Контраст**: реальные пары на экране (включая текст на фото, замер `palette.py`) — AA 4.5 / 3 / 3. Для «выбрано» достаточно разницы светлоты ≥ 3:1 — значок поверх не добавлять.
- **Иврит / RTL / 50+**: начало строки справа; шеврон и стрелка — только иконкой, не символом (`‹ › < >` в ивритской строке → находка даже если сейчас смотрит верно), зум каждого: «вперёд» влево, «назад» вправо; составные числа («1,240 / 1,800 ק״ל») единым LTR-прогоном, знак и единица с читаемой стороны; горизонтальный скролл начинается справа; ₪ и числа по `tokens.md`; размеры — по нормам платформы (не «≥ 17 / ≥ 48 для 50+»); **50+ = понятность** (P15): действие словом, подписи у нестандартных иконок, нет жеста без кнопки — нарушение → находка; символ-статус у слова («מושכר ✓») → находка; аватар-инициалы вместо фото → находка.
- **Система**: приёмы в бюджете (≤ 2) и применены одинаково; акцент не в хроме; статусы по семьям STATE; у каждого образа ответ «что сообщает».
- **Только теперь** — «## Дизайн» и записка: доводы закрывают находки? Нет — находка остаётся. Каждый пункт «Не проверено» и «Где сомневаюсь» пройти явно и записать итог.

## 6. Границы
Решений не меняет; крупное возвращает исполнителю через лида. «Некрасиво» без правила и места не пишет. Себя как дизайнер не проверяет.
