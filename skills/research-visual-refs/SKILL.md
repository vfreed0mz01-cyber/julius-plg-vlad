# Рефы по уровням и разбор (В3 + В4)

Поиск, источники, картинки — `shared-research-howto`. Замер — `research-visual-anatomy` (`palette.py`). ID и доска — `research-visual-board` §1. История — `log.md`.

## 1. Вход
- `style.md` → «Базовый стиль ✓» — **обязателен**; без него скилл не запускается.
- `plan.md` — блоки (ID, задача, ограничения, запросы), страницы, детали, места для приёмов.
- Утверждённые кадры (node id из STATE), листы решений — «куда у нас». STATE, бриф (регистр, 50+, RTL), `niche.md` и `niche-<экран>.md` (механики), `model.md` (реальный контент).
- `shared-taste` §0 + §0а (линза) — чем оценивать. Пример из `good/` — только если ход решает задачу экрана, с пометкой «из галереи».

## 2. Уровни и нормы
| Уровень | Сколько | Откуда | ID | Что ищем |
|---|---|---|---|---|
| **Композиция** | 1 на наш экран | выбранный стиль, живой | `Э<№>-<n>` + «композиция» | как целый экран держит героя, ритм, число акцентов, плотность |
| **Страница** | 6–10 | только выбранный стиль, живые | `Э<№>-<n>` | верх (первые 300–400 pt), ритм групп, где крупное, как держит пустоту (P17) |
| **Блок** | 3–5 на блок | любая ниша, ≥ 2 живых от ≥ 2 продуктов | `Б<блок>-<n>` | как строят блок с **той же задачей**; сначала якорный экран |
| **Анти-реф** | 1–2 на экран | живые, та же задача | `А<№>-<n>` | что **не** делать; строка «чем плохо» по `shared-taste` §2 |
| **Детали** | 10–15 кропов | выбранный стиль | `Д<n>` | заголовки экрана и секции, разделитель, чип, таббар (активное), поле, число + валюта, пустое состояние, заглушка фото |
| **Приёмы** | 8–12 | любые, концепты ок | `П<n>` | необычное построение блока; 1–2 станут фирменными |

- **Сначала композиция, потом блоки**: блочные рефы вписываются в её правила; на экран ≤ 2 заимствованных приёма, третий — вместо снятого. Проверка: в `refs.md` у каждого экрана `Э`-реф «композиция» стоит раньше первого `Б`.
- Кроп блока — блок + контекст 8–16 pt. Решённое Владом не ищется заново.

## 3. Цельность (анти-Франкенштейн)
Базовый стиль один. Чужой блок или приём берётся **построением, не внешностью**: радиусы, цвета, шрифты, тени → токены базового стиля; «как обыграть у нас» пишется в наших токенах («стопка из 3 карточек, смещение 8, радиус 16, фон — поверхность 2»). Приём, не работающий без своей внешности (неон, 3D), — не выше «настроение».

## 4. Карточка разбора — на каждый реф
```
### Б4-2 · <продукт — экран> · живой | концепт
Кроп: crops/B4-2.png · Источник: <mobbin_url / ссылка> · Уровень: блок · Куда у нас: Б4 <блок>, экран №<N> (<node id>)
**Что хорошо (с числами):** …
**Почему практично / красиво:** задача пользователя, принцип P… · ритм, пропорции, контраст, воздух — числами
**Слои поверхности:** плоско | база · свет · тень внутри · кромка · внешняя тень; откуда свет (для стекла, глубоких кнопок, свечения — обязательно)
**Принцип:** работает, потому что … / ломается, когда … (правило, не форма: «тёмная панель-герой — потому что одна на светлом экране; с двумя — нет»)
**Что отвечает пользователю и какая механика это держит:** вопрос, с которым он пришёл → чем приём отвечает; какие данные, действие, порядок работают у живого продукта и почему (`research-patterns`, `niche-<экран>.md`); концепт → «механики нет»
**Как обыграть у нас:** в токенах базового стиля, на реальном контенте
**Риски:** длинный иврит · контраст · зеркало (RTL) · auto-layout · 50+
**Линза (shared-taste §0а):** Л1 ✓/✗ (где) · … · Л8 → баланс: скучно | норм | перегружено; расходится с вкусом: нет | п. N — чем хорош
**Вердикт:** брать | идея | настроение — одна строка почему
```
- Числа: размеры, отступы, радиусы, кегли, веса, hex, пропорции («сумма 34 / подпись 15 = 2.3», «между группами 32, внутри 8»); pt по оригиналу, по превью — «≈».
- Нет строки «Принцип» → реф не принимается; нет ответа пользователю → не выше «настроение».
- **Линза → вердикт**: «скучно» → не выше «идея»; «перегружено» → не выше «настроение» или отдельный приём; Л1 ✗ → не «брать». Непохожий на `good/` реф с «норм» — полноценный кандидат; хорош по линзе, но расходится с `shared-taste` → раздел «Расходится с вкусом», не отсеивать.
- **Вердикты**: брать — построение в наш блок; идея — решает Дизайн вместе со стилем; настроение — только атмосфера.
- **Риски — конкретно, с числом**: «статус из 3 слов не влезет в пилюлю 28 → одно слово», «белый 15 на фото — AA только с затемнением ≥ 40 %», «иконка без подписи непонятна для 50+ → подпись словом».

## 5. Приёмы (8–12)
Приём — необычное построение блока, не украшение (вырез-угол под иконку; стопка карточек; плашка наезжает на фото; двухтоновый заголовок; шкала этапов вместо кольца). Карточка = §4 + строки:
```
**Как устроен:** геометрия, слои, числа
**Что сообщает:** смысл формы («вырез = билет»; «стопка = их несколько, верхний — главный»)
**Где уместен у нас:** блок + экран; где НЕ уместен
**Риски:** RTL (асимметрия зеркалится?) · макс. длина иврита · контраст · 50+ · auto-layout · разработка
```
- **Бюджет**: 1–2 фирменных приёма на продукт, повторяются во всех местах одного типа. Проверка: «брать» среди `П` ≤ 2.
- Приём, **меняющий видимость или порядок** (стопка скрывает, карусель прячет, раскрытие меняет порядок чтения) — в Ресерче не решается: метка «через проектировщика Спеки», лиду (P12 / P16). Приём на месте решения Влада — предложение, не замена.
- **Доноры приёма** (✓ Влад 22.11, `screen-composition` §3 п. 10): на блок-ответ главных экранов — 2–3 кандидата **вне ниши**, найденных по глаголу пользователя (Mobbin по задаче в других категориях; предметы и места из жизни аудитории — из «культурной детали» `niche.md`; каталог ходов — `v2/research/product-designers-practice-2026-11-22.md` §2). Карточка: что за предмет / экран · глагол · 3 правила, которые он приносит · что НЕ переносим · картинка. Раздел `## Доноры приёма` в `refs.md`; в бюджет «брать ≤ 2» не входят — выбирает дизайнер.

## 6. Итог по блокам
Для каждого блока: рекомендованный реф (ID), что берём, чем лучше остальных — одной строкой; 1–2 кандидата в фирменные приёмы с причиной. Решает Влад на остановке ②.

## 7. Формат выхода
`02-research/visual/refs.md`:
```
# Рефы: <проект> · базовый стиль <…>
## Композиция и страницы        ### Э1-1 … (карточка; у композиции — пометка)
## Анти-рефы                    ### А1-1 … — чем плохо (1 строка)
## Блоки                        ### Б1 <блок> — задача: … · рекомендую Б1-2, потому что …   #### Б1-1 … (карточка)
## Детали                       ### Д1 …
## Приёмы (бюджет 1–2)          ### П1 … (карточка приёма)
## Доноры приёма                 ### ДП1 <блок> — <предмет / продукт> — глагол · 3 правила · что не переносим
## Кандидаты в фирменные приёмы
## Через проектировщика Спеки (меняют видимость / порядок)
## Расходится с вкусом          - <ID> — хорош по линзе (Л…), расходится с shared-taste п. N: <чем>; чем хорош: … → решение Влада
## Что не нашлось / не смотрели
```
`crops/<ID латиницей>.png`, `crops/src/` — исходники. Разбор — только в `.md`; на доску — кроп + 3 строки.
