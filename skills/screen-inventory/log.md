# Инвентарь экрана

> v0 (2026-10-23). Урок разбора Squad / Tenderflow / Mayors K6 с Владом 23.10: правила в `shared-taste` и `critic-design` были, но ничего не мерилось — критик ставил ✓ от руки и пропускал 4 веса, 5 акцентов, тень + обводку на каждой карточке. Влад: «самое важное — грязно очень». Грязь — это не вкус, а разнобой, который можно посчитать.

## 1. Когда и кто
- **Дизайнер экрана** (`visual-designer`) — после сборки кадра, до двух самоитераций (`design-screen` §2 шаг 7): таблица говорит, что чинить первым.
- **Критик дизайна** (`design-critic`) — **проход 1**, до слепого просмотра: таблица — факты, остальные проходы — смысл.
- Лид прикладывает таблицу к показу Владу (вместе со скриншотом).

## 2. Как запустить
1. `inventory.js` → вставить в `use_figma`, заменить `FRAME_ID` на id кадра. Возвращает JSON. Сохранить в `04-critic/inventory/<экран>-<вариант>.json` (у вариантов — по файлу на каждый).
2. `python inventory_check.py <json> --profile <mobile-card|desktop-table|desktop-dense> [--premium] [--layered] [--md <экран>.md]`
   - профиль — из карты композиции экрана (`screen-composition`); нет карты → `mobile-card` для 390, `desktop-table` для ≥ 1024;
   - `--premium` — если в паспорте направления «строго / премиум / как Apple» (образ заказчика Mayors);
   - `--layered` — только если в STATE есть запись «глубина со слоями · реф-опора · выбор Влада».
3. Таблицу — в отчёт целиком, без пересказа.

## 3. Что считается и что значит ✗
| показатель | о чём говорит | типичное лечение |
|---|---|---|
| веса > 2, кегли > 5 | типографика без системы | оставить 2 веса; кегли — шкала из `tokens.md` |
| контраст кеглей < порога | «вайрфрейм»: всё одного размера, героя нет | один крупный элемент (цифра / заголовок) ≥ 3–4× подписи |
| серые > 3 | три оттенка «серого на глаз» | ступени одного цвета текста (`ink/1–3`) |
| радиусы > N значений | радиус случайный, не по типу элемента | радиус = тип элемента (`good-24`) |
| акцентные оттенки > N | цвет без роли, факт раскрашен как предупреждение | один акцент = действие; статусы — семьи из STATE |
| тень + обводка на узле | элемент «одет» дважды | либо тон, либо волосяная обводка |
| одинаковая пара подряд > 2 | «жирный + серый» пять раз — лента | сменить форму третьего блока или собрать в строки |
| блоки-клоны > 2 | карточки-клоны вместо списка | строки с воздухом (`good-11`), один шаблон строки |
| крупных образов > 1 | два героя на экране | один герой; второй — иконкой / в строке |
| первичных кнопок > 1 | нет главного действия | одна залитая, остальные тихие одного стиля |
| ряды контролов разной высоты | кнопка 48 рядом с чипом 36 в одной строке | одна высота на ряд |
| заливок без переменной > 10 % | значения мимо токенов | привязать / дыра токенисту |
| % кадра без содержимого > порога (0.6.1) | **недобор**: вайрфрейм / «избегательная эстетика» — всё вычищено, взамен ничего | герой, типографский акцент, собранная группа (`shared-taste` §2 телл 28) |
| разрыв > порога, px (0.6.1) | ничейная пустота между блоками (не ритм) | ритм 1:2:3 или опора внизу (`good-26e`) |
| ведущая цифра / следующая < 1.3 (0.6.1) | числа одного размера — KPI не читается | одна ведущая ≥ 1.3× (премиум ≥ 1.6×), остальные тише |
| иконок в кружках > порога (0.6.1) | «иконка в бледном кружке» — дефолт дашбордов (B2B: 0) | иконка в вес текста без подложки, или все в одинаковых кругах по паспорту |
| высота строк списка вне 36–53 (0.6.1) | строки-карточки (слишком высокие) или давка | профиль плотности: desktop-table 36–53, dense 32–48 |

Пороги плотности и недобора — из ресерча 23.10 (`v2/research/agents-premium-ui-2026-10-23.md`: Taste Skill `app-screens.md` — профиль 23 дашбордов, `rules.mjs`; Hallmark gates 77 / 79). Они меряли код, мы — узлы Figma: перенесены числа, не код.

Показатели с порогом `—` для профиля не считаются (в таблице-списке клоны и повторы — норма).

## 4. Режим Б (✓ Влад 23.10)
Превышение — **не возврат**. Дизайнер в «## Дизайн» пишет по каждому ✗ одну строку: **починил** (что) или **оправдано** (почему: «терминал — три семьи статусов по STATE»).
**Снятие порога — только с причиной** (0.6.1, из Hallmark gates / Auteur slopscan): «оправдано» без причины из задачи пользователя, STATE или образа заказчика — не снятие, а ✗; формальные («так в рефе», «так красивее», «для разнообразия») не принимаются. Лид ведёт в STATE раздел **«Снятия порогов»**: показатель · экран · причина · дата. **Один показатель снят > 3 раз подряд с одной и той же причиной → это уже стиль проекта, не исключение**: порог переписывается в `03-design/thresholds.json` проекта (с записью решения Влада), а не снимается четвёртый раз. Так пороги калибруются по живым экранам, как Влад и хотел. Критик проверяет эти строки, не считает заново. Влад видит таблицу и экран вместе — и либо соглашается с оправданием, либо правит порог в `thresholds.json` проекта (копия в `03-design/thresholds.json`, если проекту нужны свои). Когда пороги устоятся — режим А (возврат до прохода) обсуждается с Владом отдельно.

## 5. Варианты
У 2–3 вариантов одного экрана — таблица на каждый + строка «чем отличаются по инвентарю» (напр. «A: 1 акцент, тени 0; B: 2 акцента, тени 4»). Варианты с одинаковыми таблицами — не разные варианты (`design-screen` §3а «различимы за 5 секунд» теперь проверяется и числом).

## 6. Границы
Скрипт не знает смысла: он не отличит факт от предупреждения и героя от декора — это критик (`critic-design` §3). Не меняет Figma. Не лечит сам. Пороги — стартовые, не закон: калибруются по экранам, которые Влад принял.
