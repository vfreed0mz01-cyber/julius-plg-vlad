# Сборка дизайн-системы (Figma)

> v0 (2026-09-30). Влад ✓: дизайн-система живёт на странице `Design System` в файле вайрфреймов проекта + Figma variables; отдельная библиотека — когда появится второй проект.

## 1. Когда и кто
- После `design-tokens` (tokens.json прошёл `tokens_check.py`).
- Агент `ds-builder`. Сначала загрузить `figma-use`. Пилотом — только то, что нужно экрану-пилоту.

## 2. Где
- Страница **`Design System`** в файле вайрфреймов. Если страницы нет — создать (решение Влада 30.09 для Mayors; в новом проекте сначала спросить Влада). Секции: `Tokens / Color`, `Tokens / Type`, `Tokens / Space & Radius`, `Icons`, `Components`.
- Имена слоёв, переменных, компонентов — английские; образцы текста — иврит.

## 3. Переменные и стили
- Коллекции: `Primitives` (шкалы) → `Semantic` (роли, значения — алиасы на примитивы). Режим пока один (`Light`).
- Отступы и радиусы — переменные `space/*`, `radius/*` (FLOAT).
- Шрифты — text styles по ролям (`Body`, `Title`, `Amount/L` …); перед использованием `loadFontAsync`, проверить, что семейство и вес есть в Figma (у Mayors: Julius ставит Влад локально — если шрифта нет в среде, остановиться и сообщить, **не подменять** другим).
- Значения — только из tokens.json. Нашёл дыру (нужного токена нет) → в отчёт токенисту, не придумывать.

## 3а. Материалы (если направление «со слоями»; ✓ Влад 03.10)
- Урок: поверхности собирались одной заливкой — Влад: «в Figma всё реализовано очень упрощённо, прям максимально», а в рефах «несколько наложений цвета, внутренней тени, оттенков». Упрощать материал до одной заливки — провал.
- Материалы из `tokens.json` (`materials`) собираются **первыми, до компонентов**: стиль заливки `Material/<имя>` (несколько красок по порядку) + стиль эффектов `Material/<имя>` (+ стиль обводки, если есть). Компонент берёт материал целиком, не пересобирает слои.
- Проверенные рецепты слоёв и грабли API — `materials/recipes.md`. Нового материала нет в рецептах → собрать по строке «слои поверхности» из разбора рефа и добавить рецепт.
- Сдача: плитка-образец каждого материала **рядом с кропом рефа** в одном масштабе, скриншотом.
- **Материал — не украшение** (Влад 04.10, «эффекты без логики — нейрослоп»): он задаётся для мира экрана (фон + поверхности), у него один источник света и причина. Не ставить громкий материал на элемент, который повторяется в строках списка или карточках сетки; на странице из плоских карточек материалов нет вовсе. Рецепты `materials/recipes.md` — способ собрать поверхность, **которую выбрал паспорт направления по рефу**, а не набор эффектов на выбор.
- Направление «плоско» — раздел не применяется, материалы не заводить (Влад: «не для каждого проекта»).

## 4. Компоненты
- **Компоненты — в языке выбранного стиля, не копии кита** (✓ Влад 30.09, урок пилота №1 v1). Кит WF/* даёт только перечень нужных компонентов и их данные / состояния; форма, поля, разделители, кегли, расстановка — из паспорта стиля и приёмов рефа (`refs.md`, бриф языка стиля в `03-design/`). Имена свойств можно сохранить для удобства, но «похоже на кит» — провал.
- Auto-layout везде; заливки, обводки, отступы, радиусы **привязаны к переменным**; текст — к стилям.
- RTL: направление и выравнивание по началу строки справа; иконки со смыслом направления — зеркальные варианты (разметка из `assets.md`).
- Зона нажатия ≥ параметра проекта (у Mayors 48), даже если видимая часть меньше.
- Иконки: SVG набора из `assets.md` (у Mayors Phosphor, MIT) → `figma.createNodeFromSvg` → компонент `Icon/<name>` с вариантом `Weight` (Regular / Fill), цвет — переменная. Lucide запрещён.
- **Линейные образы (эскиз здания П9 и т. п.) без векторизации** (Влад 30.09): чёрно-белый PNG → группа `Sketch`: снизу `sketch/line` (цвет линий — переменная), над ним PNG с `isMask = true`, `maskType = LUMINANCE`, сверху `sketch/surface` (цвет поверхности — переменная). Белое PNG = поверхность, чёрное = линии; цвет меняется переменной, картинку не трогать. В RTL отражать PNG (`relativeTransform [[-1,0,w],[0,1,0]]`), здание — у конца строки.
- Системные элементы iPhone — настоящие компоненты Влада (у Mayors status bar `171:4615`, home `171:4635`, клавиатуры `171:5864`), не рисовать свои.

## 5. Линт (перед сдачей)
Обход всех узлов страницы: (1) **UNBOUND** — заливка / обводка / отступ / радиус без привязки к переменной; (2) **STOCK COLOR** — любое значение ≈ стоковому (список — `design-tokens/tokens_check.py`); (3) **TEXT-SQUEEZE** — короткий лейбл порвался на 2+ строки (лечение — HUG / ширина, не кегль); (4) **FONT** — стиль не найден / подменён. Отчёт `LINT: чисто | N — список` прикладывается к отчёту.

## 6. Выход
Страница `Design System` (node id секций) · `03-design/components.md` (компонент · варианты · какой WF/* заменяет · токены) · скриншот каждой секции · отчёт лиду.

## 7. Границы
Не меняет значения токенов, не рисует экраны, не трогает кадры вайрфреймов и их кит.

# Материалы: проверенные рецепты слоёв (Figma)

> v0 (2026-10-03). Собраны пробой «Materials Lab (test)» по рефу `shared-taste/good-18` — Влад: «то, что ты сделал в Figma, ахуенно выглядит». Картинка: `lab-test-2026-10-03.png`. Значения — отправная точка: цвета и размеры каждый проект берёт из своих токенов, **строение слоёв** сохраняется.
> Материалы — только для проектов, где направление выбрано «со слоями» (Влад: «не для каждого проекта»).

## Когда НЕ применять (Влад 04.10 — «эффекты без логики, нейрослоп», `shared-taste/bad/11`)
- В паспорте направления нет «со слоями» по выбранному рефу → рецепты не открывать.
- Страница плоская (белые карточки на светлом фоне) → материал на одной-двух деталях выглядит приклеенным.
- Элемент повторяется в строках списка или в сетке → громкий материал умножится и станет шумом.
- Значения отсюда не копировать «потому что красиво»: это проба по одному рефу (`good-18`), тёмный прибор.

## Общие правила
- Материал = **заливки по порядку (снизу вверх) + обводка + эффекты** на одном узле. Не рисовать слои отдельными прямоугольниками.
- **Один источник света на продукт** (в рецептах — сверху): блик на верхней кромке, тень внутри снизу.
- Объём — **внутренними тенями**; внешняя тень одна, мягкая, тонированная (цвет материала или фона), не серая.
- Свет на цветной плитке — **цветом самой плитки** (светлее), не белым.
- На продукт 2–3 материала; у остальных поверхностей — плоская заливка.

## Глубокая кнопка
**Акцентная пилюля** 220 × 96, радиус 48: SOLID акцент + GRADIENT_LINEAR сверху вниз (белый 28 % → 0 % (0.45) → тёмный тон акцента 35 %); effects: INNER белый 60 %, y 2, blur 2 · INNER тёмный тон акцента 55 %, y −8, blur 14 · DROP акцент 28 %, y 14, blur 36, spread −8. Растр: сетка эллипсов 11 × 11 px, диаметр 1.5–4.7 и прозрачность 25–70 % растут к центру, `clipsContent = true`.
**Тёмный круг** 96: SOLID `#151516` + GRADIENT_LINEAR (белый 9 % → чёрный 30 %); stroke 1 px INSIDE, белый 14 % → 2 %; effects: INNER белый 10 %, y 1.5, blur 2 · INNER чёрный 60 %, y −8, blur 14 · DROP чёрный 70 %, y 14, blur 28, spread −6.
**Канавка тумблера:** белый 10 % + INNER чёрный 60 %, y 3, blur 6 + INNER белый 12 %, y −1, blur 1; ручка — светлый круг с радиальным бликом, INNER чёрный 18 %, y −3, blur 5, DROP чёрный 50 %, y 6, blur 12.

## Грабли API
- Цвет в стопах градиента и в эффектах — `{r,g,b,a}`; в SOLID — `{r,g,b}` + `opacity` у заливки.
- `gradientTransform`: единичная матрица `[[1,0,0],[0,1,0]]` для радиального = по центру на весь узел; сверху вниз для линейного = `[[0,1,0],[-1,0,1]]`.
- Эффект `NOISE` через API не принимается (ошибка валидации) → зерно кладётся картинкой-заливкой (`upload_assets`), режим наложения поверх.
- Текст на материале: контраст считать по **худшей точке** материала (самое светлое / тёмное место под текстом) — токен `check/*`.
