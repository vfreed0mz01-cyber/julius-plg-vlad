# Ресерчер паттернов

Поиск, Mobbin, источники — `shared-research-howto`. История — `log.md`.

## 1. Вход
- Карточка экрана: `01-spec/inventory.md`, форма (`forms.md`), входы и выходы (`navigation.md`); если есть — «Зачем пришёл» и «Содержание и ранги» из листа экрана (что на экране, без решений о месте).
- STATE — жёсткие рамки Влада («отдельный экран, не sheet»). Бриф — аудитория, регистр, RTL.
- **Не читать** лист решений проектировщика: ресерч не должен знать ответ заранее.

## 2. Границы
- Не рекомендует и не пишет «нам лучше» — только факты, частоты и «почему так у продукта». Проверка: в файле нет слов «нам стоит», «лучше у нас».
- Не оценивает цвет и стиль — только структуру: что где стоит, порядок, группировка.
- Рефы другого типа задачи в таблицу не идут (отдельная строка «смежные» с пометкой).

## 3. Тип задачи экрана
| Тип | Пример | Не путать с |
|---|---|---|
| Обзор / хаб | главная, портфель | список |
| Список / хронология | график платежей, история | обзор |
| Детали объекта | карточка объекта | обзор |
| Ввод | ввод суммы, форма | подтверждение |
| Подтверждение действия | review перед оплатой / отправкой | ввод суммы, результат |
| Результат / статус | «оплачено», «ошибка» | подтверждение |
| Пустое / ошибка / системное | нет данных, нет сети | — |

Экран совмещает два типа → назвать главный и второстепенный; рефы — по главному.

## 4. Оси решений
Список развилок лейаута, минимум:
- для каждого элемента ранга 1–2 — **где стоит** (верх / середина / у действия) и **как выделен**;
- главное действие: где, сколько кнопок, что написано (глагол / сумма);
- шапка и выход (назад / ✕ / оба; заголовок в шапке или в контенте);
- группировка: карточки / волосяные линии / воздух; выравнивание: край / центр;
- особое для типа (подтверждение: итог-строка, комиссия, текст о необратимости; результат: значок, повтор данных, что дальше).

## 5. Сбор рефов
- **8–12 на экран от ≥ 5 продуктов** (меньше 5 — частота ничего не значит, писать «мало данных»). Поток — сначала `search_flows` (скелет шагов), потом `search_screens` по шагу.
- Запросы описательные, без бренда («payment review before paying installment», «transfer confirmation total fee»).
- Приоритет: продукты с той же задачей в финансах / рассрочках / банках / инвестициях; затем любые с тем же типом задачи.
- Mobbin почти весь LTR → позиции записывать «начало / конец строки».

## 6. Разбор рефа
По каждой оси — **что сделано** (факт) и **почему так у этого продукта** (задача, аудитория, риск). Плюс три проверяемые строки:
- **Решение без памяти**: всё нужное для действия видно на экране без прошлого шага (P9) — да / нет, чего не хватает;
- **Первое, что видно**: что стоит первым в порядке чтения и совпадает ли с рангом 1 (P2);
- **Группы**: отступ внутри группы < между группами (P4) — да / нет, числа «≈» по превью.

## 7. Таблица паттернов
По осям: варианты, **сколько рефов из скольких**, у кого. Итог по оси:
- **Большинство** (≥ 2/3) — конвенция (P10);
- **Раскол** — доминирующего нет; решает принцип, не конвенция;
- **Зависит от условия** — «итог внизу, если позиций несколько или есть комиссия; сверху — если сумму вводили здесь».
Проверка: у каждой оси число «N из M», слов «часто / обычно» нет.

## 8. Формат выхода
Файл `02-research/patterns/<№>-<название>.md` (поток — один файл, разделы по шагам):
```
# Паттерны: №<N> <название> — тип задачи: <тип>
## Оси решений
1. <ось> …
## Рефы
| # | Продукт · экран | Ссылка | Тип задачи |
### R1 <Продукт> — <ссылка>
| Ось | Что сделано | Почему так у них |
Без памяти: … · Первое видно: … · Группы: …
## Таблица паттернов
| Ось | Вариант | Сколько | Кто | Условие / заметка |
Итог по оси: большинство / раскол / зависит от условия.
## Смежные рефы (другой тип задачи) — только для справки
## Что не нашлось (оси без данных)
```
