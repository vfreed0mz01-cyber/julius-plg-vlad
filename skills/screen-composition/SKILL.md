# Карта композиции экрана

## 1. Когда и кто
Дизайнер экрана (`visual-designer`) — после прочтения одной строкой (`design-screen` §2 шаг 1), до эскизов и первого кадра. На экран одна карта; у вариантов — на каждый (варианты расходятся картой, не цветом). Файл `03-design/screens/<экран>-composition.md` (вариант — суффикс `-A`).

## 2. Карта (все строки обязательны, ≤ 1 страница)
```
# Композиция · <экран> · <вариант>
Вопрос пользователя: <с чем пришёл — из листа экрана «Зачем пришёл»>
Ответ на экране:     <один элемент, который отвечает>
Герой:               <объект | цифра | фраза | образ> — <что> — <почему он> — <×N к подписи>
Действие:            <одно первичное; где; текст = результат, не глагол>
Второй план:         <1–2 блока; чем тише героя (размер / цвет / место)>
Фон:                 <остальное — строками / одним ритмом, без своей формы>
Плотность:           mobile-card | desktop-table | desktop-dense — <почему: сравнивает N строк / читает один объект / действует>
Ранги полей (списки): первичные (1–2) · вторичные (2–3) · в деталь (остальное)
Ритм:                внешний <N> · внутренний <N> · в строке <N>  (из tokens.md; между секциями ≥ 2× внутреннего)
Приём 1:             <что> — реф <ID> — работает потому что … / ломается когда … — отвечает на вопрос: …
Приём 2 (или «нет»): …
Донор приёма:        <нет | предмет / продукт чужой ниши — глагол пользователя — 3 правила, которые переносим — что НЕ переносим — блок> (обязателен у варианта «на грани»; в среднем — можно; правило 10)
Запрещённые дефолты: <shared-taste §2, каждый пункт: нет | есть, потому что …>
Reflex-check:        (а) что поставил бы ИИ по умолчанию: … (б) что поставил бы ИИ, избегающий (а): … (в) наше — и чем отличается от обоих: …
Свои теллы:          <2 приёма, которые здесь НЕ делаем, хотя приходят первыми, — и почему>
Вариативность:       <чем отличается от последних 3 экранов проекта и от 3 прошлых версий этого экрана (герой / плотность / ритм / донор) — или «тот же каркас намеренно: …»>
Регистр:             <строка из niche.md, вывод «какой визуал подходит аудитории» (`research-niche` §6, раздел «Вид ниши · Вывод для Дизайна»): кто смотрит → строгий / тёплый / игровой>; акцент: 1 | 2 (почему два)
Премиум (паспорт «строго»): герой / основной ≥ 2,5 (мобайл; десктоп и журнальный — 4) · 1 акцент · волосяные линии · ритм 1:2:3 · один материал — каждый: как
```
Проверки строк: «Регистр» = цитата строки вывода «какой визуал подходит аудитории» из `niche.md` (в старых нишах без вывода — паспорт направления из STATE с пометкой «ниша без вывода»; ни того, ни другого → карта не принимается); «Свои теллы» — 2 приёма названы и на кадре отсутствуют; «Reflex-check» — (в) не совпадает с (а) и (б) содержательно, не отрицанием; «Вариативность» — три экрана подряд с одним каркасом без «намеренно» → находка.

## 3. Правила (хозяин — этот файл; `design-screen` §3 и `critic-design` §3 ссылаются сюда)
1. **Один герой.** Второй крупный образ / вторая крупная цифра / повтор героя ниже (та же карточка, фото того же объекта) = два героя → находка. В таббаре — иконка, не герой. Инвентарь: `heroes ≤ 1`.
2. **Герой может быть типографским** (`good-34`): крупная тонкая цифра ≥ 3–4× подписи. Картинка не обязательна.
3. **Плотность от задачи, не от платформы.** 5+ одинаковых сущностей, которые сравнивают, → `desktop-table` / строки (`good-11`); один объект → карточка / сцена. Мобильная карточка на 1600 px → находка.
4. **Ранги полей до раскладки.** В строке списка один акцент (название или число); факты (условия, суммы) не раскрашены как предупреждение (`critic-design` §3).
5. **≤ 2 приёма на экран**, у каждого реф-ID, принцип (работает / ломается) и вопрос пользователя. Приём без принципа или без ответа «что сообщает» → не берётся.
6. **Повторы ≤ 2.** Третий блок той же формы подряд меняет форму или собирается в список (`good-23`). Инвентарь: «пара подряд ≤ 2», «клоны ≤ 2».
7. **Одинаковые сущности — одна форма.** Статус — одна форма на экран; кнопки второго уровня — один стиль; табы ≠ чипы ≠ бейджи.
8. **Премиум — чек-лист наличия.** «Убрать всё» = вайрфрейм (`shared-taste` §2 телл 28); строгий экран держится на контрасте кеглей ≥ 4, одном акценте, волосяных линиях, ритме 1:2:3, одном материале — у каждого пункта в карте «как».
9. Критик (проход 3) проверяет: карта есть; герой один и на экране там, где заявлен; плотность обоснована задачей; приёмы с принципом; заявленное = на кадре.
10. **Донор приёма** (✓ Влад 22.11, `shared-taste/taste-log.md` §0.8.0): смелый ход берётся не из ниши и не выдумывается, а переносится **из чужой области или физического предмета** из жизни аудитории (стена почтовых ящиков, корешок квитанции, табло, билет, Wallet / Family / Things / Teenage Engineering). Ищется по **глаголу пользователя** («увидеть, кто не…», «подтвердить деньги»), не по нише. Переносятся **правила** предмета (порядок, вес, стопка, что видно без чтения), не фактура (без скевоморфизма). **Ровно один** донор приёма на вариант, на блок, отвечающий на вопрос экрана (P19). Проверка удалением: без приёма экран не хуже → снять. 50+: метафора знакома, статус ещё и словом, жест дублирован кнопкой. Вариант «на грани» — обязателен; средний — можно; «аккуратный» — нет.

## 4. Связь
«Зачем пришёл» и ранги — из листа экрана (`spec-screen-logic`), карта их переводит в композицию, не меняет. Профиль и модификаторы → `screen-inventory` (`--profile`, `--premium`). Таблица перевода поблочно (`design-screen` §2 шаг 4) — после карты и в её рамках. Развилка композиции (герой А / Б) — Владу эскизом (`shared-lead` §6).
